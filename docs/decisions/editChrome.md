# editChrome (wave 45, HOM-07, HOM-12)

**Status: built (JVM and Robolectric tested; nothing is device verified).** The owner said the editing experience was "bonkers". `docs/research/home-editing.md` diagnosed it (section 1) and proposed the chrome (2a, 2e, 2f, stream C). This is stream C: the chrome of the single-page home edit mode and its entry and exit. Selection, handles and resize of items are the handles stream's (`WidgetEditUi.kt`, `HomeExtrasUi.kt`, `HomeItemsHost.kt`); the strip-and-tabs page editor is stream D's and is only reached from here.

## Owner decisions (asked and answered)
One Done only, in a top bar. The hint is a single line under the top bar for the first 3 entries into edit mode, never a toast. The left side notification tray is hidden while editing.

## What it is
- **Entering.** Long press, Ground Control "Edit home" or the sheet row open the page itself: the live home layer animates to scale 0.88 (emphasized curve, 300 ms in, 250 ms out; reduced motion: the page is at rest from the first frame and the scrim cross-fades in 120 ms). Content stays fully live. A 35% black scrim lies round the page (outside its 20 dp rounded rectangle), a 1 dp 12% white hairline draws the page edge.
- **Grid dots.** One `Canvas` in the page view draws a 2 dp dot at every cell corner (18% white, 40% within one cell of the active rectangle). `EditGridState.update(rect)` is the API for the handles agent: the rectangle is in the page grid's own px (the page area, the same space as `GridGeometry`); `LocalEditGrid` carries it. The dots read it in the draw lambda, so a drag never recomposes the page.
- **Top bar** (56 dp inside the safe area, over a soft dark gradient; it swallows touch over itself): Cancel (48 dp text button), the title "Editing page N of M" (14 sp, a heading, first in traversal order, tapping it opens the page editor), Undo and Redo (48 dp icon buttons, content description with the count: "Undo (3)", "Redo (2)"; disabled ones at 38%, enabled at full white), and the one Done (48 dp high, tonal). The old floating pills and the toast-like banner are removed (`HomeEditBar` remains only as the page editor's bar, without the banner).
- **Hint.** "Drag to move. Tap an item to resize or change it." under the bar, for the first 3 entries only. The count is `EditChromeStore` (file `edit_chrome`, `TolerantPrefs`, device-local: excluded from backup and transfer like `preview_window`), written on entry from an effect, never from composition. It fades after 4 s or on the first touch of the screen (the home's existing touch observer). Opening the page editor drops it.
- **Tray** (72 dp, above the dock when a bottom dock is shown, else above the page dots / the system inset): Apps (the app picker, "Add an app"; a pick goes to the first free cell of the page being edited, "Page full" otherwise), Widgets (the existing widget picker request), Folders (the existing New folder dialog), and "+ Page" only with Pages Paginated or Continuous (the one add-an-empty-page path `EditCardState.addPage`). Links, files and shortcuts stay in "Widgets, folders and icons" (Ground Control) and in the page editor's Folders tab; the tray has only the three chips the owner listed.
- **Fixed chrome.** The four hotspots and the music line dim to 40% and are inert (four squares at the page's corners and a strip under the bar swallow touch: `EditFixedChromeShield`; their semantics are cleared). The page dots dim to 40% and stay tappable, and are drawn outside the scaled, clipped page, in the window position they have on the unscaled home (inside the page they would be carried up under the dock and clipped away): a dot goes to that page in edit mode (the Glance house and the Comms glyph do nothing while editing; edit mode ends only on Done or Cancel). The dock stays at 70% (it is a drop target). The left notification tray, the Comms and Recents handles and the two edge swipes (`launchpadEdgeDrag` x2, `rightEdgeSwipe`) are off while editing, so they cannot fire during a handle drag.
- **Cancel.** `LayoutDockEditSession` now keeps the snapshot taken on entry (layout and dock pins; a window size class swap moves it) and `cancel()` returns the restore, however many changes were made (the undo stack only holds 20). The confirm dialog ("Discard changes?") appears only when something differs from the snapshot (a change that was undone is no change). Back and Esc follow the same rule (`HomeEditChromeState.requestCancel`). Done keeps and says "Saved". Both animate the page back to 1.0.
- **Accessibility and keyboard.** The bar is a traversal group with the pane title "Edit toolbar"; the title is a heading with the lowest traversal index (TalkBack starts there); every control has a label; "Editing home page 2 of 4" is announced on entry and "Saved" on Done (`announceForAccessibility` on the host view, no accessibility service); Esc is Cancel; Enter and D-pad centre activate the focused Done (a clickable does that itself).
- **Page editor.** It remains, as a step inside edit mode: the title opens it (stream D's strip and tabs, its own bar); the empty-home hint ("Long press to add apps") opens it directly with the add strip focused; Back there leaves editing with changes kept, as before. Entering it blends the 0.88 page into its card (`EditChromeGeometry.blend`).

## Geometry (pure, `EditChromeGeometry`)
Portrait scale is exactly 0.88. The page is centred and eased down by half of what the bar would otherwise cover, never past the window bottom, so the bar covers only the page's empty frame band. Landscape has no height to spare (56 dp bar plus 72 dp tray plus 8 dp is a third of a 360 dp window), so the scale is the largest that clears both, between 0.60 and 0.88: this is a deviation from "0.88" and is deliberate. The frame is computed from the home's measured size, not from the configuration, so the scrim, the outline and the layer agree.

## Not matched
- The tray in portrait overlaps the page's bottom band (the dock's footprint lies under the scaled page as well); nothing is placed there because items stop above the dock reserve, but a very full page on a small window may meet the tray.
- The scrim is drawn over the app's dark backdrop gradient, not over the wallpaper: the wallpaper is inside the scaled layer, so round the page you see the backdrop, not the wallpaper.
- Dots are white at fixed alpha: on the light theme they are faint.
- Hotspot corner widgets (live peek widgets) expand beyond the 64 dp shield squares; touches on the expanded part are not blocked.
- Cancel restores the arrangement and the dock pins (what undo covers); widget definitions, folder contents and extras written during the session are not rolled back (as with undo).
- The Glance dot and Comms glyph in the indicator are inert while editing rather than hidden.
- Not verified on a device: the transition feel, the page frame under a real status bar and gesture bar, TalkBack focus order and announcements, the dock drop target while dimmed, drag interplay with the handles stream's work.
