# editGaps (wave 48, HOM-07, HOM-12): the gaps the editor integration left

**Status: built (JVM and Robolectric tested; nothing is device verified).** Wave 47 made the home editor one editor and listed what it did not match. This wave closes those, keeping the owner's decisions: icons push aside, widgets block, an icon on an icon makes a folder, one Done, the hint shows three times.

## Decisions
1. **Size presets follow "widgets block".** `PresetFit` (core-catalog) packs the page like the grid does (`TilePacker`), keeps the widget's origin (moved back only to stay inside the grid) and asks `EditCollision.resizeVerdict`, the rule the handles use. A preset that would cover any other item is refused: the reject buzz (LongPress haptic) and the note "Can't resize: another item is in the way" (the handles' own string, already translated). Nothing is pushed. The provider-limit clamp of wave 47 runs first (the size that would apply is the one that is checked); a preset equal to the current size is never "blocked". The old reflow path (`HomeEdit.resizeWidget` in `HomeItemsHost.resizeTo`) is no longer used by the sheet; `resizeTo` now goes through `EditHandlesApply.resizeTo`, as a handle drag does. Shrinking is always free.
2. **Cancel restores what the layout session did not hold.** The layout session keeps pages and dock pins. The extras of `HomeState` (folders, item definitions, widget sizes; stacks live in the definitions) and the clock tile's settings (prefs) are noted when edit mode starts (`EditExtrasEntry`, `EditConfigEntry`) and put back by Cancel after the layout. Widgets that were added during the session are freed (their host ids). `HomeEditState.hasChanges` now also counts these, so the Discard confirm appears for a size or folder change alone. A widget's own provider configuration (what its configure activity stored in the provider) is NOT something the launcher owns and is not restored.
3. **Action bar on the scroll surface.** On Pages Continuous the cells touch each other, so "below the item" covered the icon under it (the wave 47 test avoided App 01 for this reason). `ActionBarMath.placeOnScroll`: above the item first, else below the cell under it (that cell is estimated as 1.3 icon heights plus the label room and the gap), else the top or bottom strip of the free area; the least overlap wins when nothing is free (a tall widget that fills the room). A side dock (an avoid rectangle spanning the area) narrows the area sideways. Paginated and the list/grid surfaces keep the wave 47 placement (below, flip above, 30 dp handle reach).
4. **Hint and tray clear of the dimmed hotspots.** The shield swallows a 64 dp (times the page scale) square at each page corner and a 48 dp music strip under the top bar. The hint now starts under the lowest of the top bar, that strip and the top squares (`hintTopPx`); the tray's bottom edge is raised above the bottom squares only when its requested place (the dock's or the page dots' room) would overlap them (`trayBottomDp`; in landscape the page already ends above the tray, so nothing moves). The action bar's reserves follow (`actionBarReserveDp(hintTopDp)`). The tray stays one row (a two row tray would break the 72 dp reserve used elsewhere).
5. **Page editor on small windows.** Windows under 640 dp high (320x568) trade strip card size (0.6 of default at the smallest), strip padding 4 dp, gaps 6 dp, tab row 44 dp and a content panel of 72 dp (it scrolls inside itself) for a live card of at least 0.45 of the window. Result on 320x568 with 24 dp bars: 0.45 (wave 47: 0.39 without bars, about 0.31 with). Taller windows are unchanged.
6. **Undo / Redo history.** The icons show a count badge (9+ above nine) and the description "Undo, 3 available"; a disabled one has the state description "Nothing to undo / redo". There is no hover tooltip: Compose offers none without extra surfaces on a phone; the long press description is TalkBack's. The grid dots use dark ink (alpha 0.34, 0.62 near an active drag) on the light theme (white at 0.18 vanished on a light wallpaper).

## Not matched / honest limits
- The "icon under the bar" is an estimate of the next cell (1.3 icon heights + label + gap); a surface with a very different pitch may still be covered a little. The rule is tested on the real Continuous surface for the first two icons of a column.
- A preset is checked against the TilePacker layout of the page. The scroll surface packs columns differently from the grid; the check is the same rule on the same page order, which is what the grid dots and handles also use, but it was not compared against the column fill cell for cell.
- The tray over page content: raised above the bottom hotspots it now covers the page's lower icon area in portrait (before it covered the hotspots). It does not take touches in the gaps between chips.
- Undo and Redo of the layout session do not restore the extras step by step (EditGraveyard still does that for removals); only Cancel restores the entry state.
- The page editor's live card on 320x568 pays for it with a 72 dp content panel (about one row of apps visible) and 4 dp strip padding.
- Device only: how the bar feels over a scrolling surface, the badge and the lowered hint on a real window with real insets and cutouts, haptics, TalkBack wording.
