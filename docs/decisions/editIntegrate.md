# editIntegrate (wave 47, HOM-07, HOM-12): one coherent home editor

**Status: built (JVM and Robolectric tested; nothing is device verified).** The owner said the home and page editing was "bonkers". Wave 45 built five streams in parallel (handles, action bar and sheet, chrome, page editor layout; research in `docs/research/home-editing.md`). They overlapped. This wave makes them ONE editor. Decisions of the owner stay: one Done, icons push aside, widgets block, an icon on an icon makes a folder, the side tray is hidden while editing, the hint shows three times.

## What was merged
- **One selection.** `EditSelectionState` (handles stream) now implements `ItemSelectionSource` (action bar stream). `HomeItemSelection` is deleted. The home (`HomeScreen`) owns one `EditSelectionState` and passes it to `HomeItems` (the grid, the handles, the keyboard) and to `ItemEditState` (the bar and the sheet). A tap selects, a long press selects, a long press then a drag moves; one item at a time. Surfaces without their own selection (the clock and Settings tiles, the scroll surface) select through `ItemEditState.select`, which writes the same state (the touch rect is the first bounds until the item reports its own).
- **One outline, no fallback button.** The 2 dp primary outline 3 dp outside the content is the handles stream's (`selectionOutline`, the widget frame). The bar's own outline is off (`showOutline` defaults to false). The temporary 48 dp Remove button is off (`fallbackBar = false` in the home); the code (`EditSelectionOverlay`) stays for hosts without a bar and for the live region that announces edits.
- **Measured chrome insets.** The bar used fixed reserves (64 dp top, dock + 72 dp bottom). It now reads `EditChromeGeometry.actionBarReserveDp`: top = safe top inset + the 56 dp top bar (+ the 32 dp hint line while it shows), bottom = the tray's bottom offset (the dock's or the page dots' room) + 72 dp; a dock at the start or end side is an `avoid` rectangle. In the page editor there is no tray. The bar still sits below the item, else above, grown by the handles' 30 dp reach.
- **Resize.** The bar's Resize no longer starts a mode. The handles of a selected widget are always shown; Resize calls `EditSelectionState.focusResize()` (focuses the frame, announces "Resize handles active"). `HomeItems.resizing`, `HomeExtras.resizing / onResize / onResizeDone`, and the in-widget Done are gone. The sheet's size presets are clamped by `PresetClamp` (core-catalog) against the same `CellLimits` the handles use (`HomeItems.widgetLimits`): outside them the preset applies the clamped size (nothing if it equals the current one), buzzes (LongPress haptic) and shows "Not available for this widget" under the row.
- **One bar in the page editor.** `EditTopBar` (Cancel, title, Undo, Redo, Done) was extracted from `HomeEditChrome`; the single-page edit mode and the page editor (`PageEditorHost(topBar = ...)`, title "Editing pages", no title click) draw the same composable. `HomeEditBar` (the four pills) is deleted. Cancel in the page editor restores the session snapshot and asks only when something changed (`EditCancelDialog`, shared); Esc and Back are Cancel there too (before: they left with changes kept); Done keeps.
- **No tray in the page editor.** Its tabs already hold Apps, Widgets and Folders; the "New page" card replaces "+ Page". `PageEditorGeometry.BOTTOM_BAR_DP` is 0 and `LIVE_SCALE_WISH` is 0.45 so the live card is at least 0.45 of the window height on 411x891 (with 24 dp system bars; the content panel gives way from 30 percent to about 22 percent first). Landscape and tablet layouts are unchanged.
- **Grid dots.** `EditGridState.layer` (the dots layer's coordinates) lets a ghost convert its box to the page grid's px at any page scale. The widget frame calls `update(rect)` while a handle is dragged and `clear()` on release; the page's drag of an icon or widget calls it with the dragged item's (or the widget's cells') rectangle. The frame's own dots are drawn only where the page has no dots layer.
- **Leftovers removed.** The icon and tile remove badges (`EditHandleBox`, `HomeEditHandle.kt`), `HomeItemSelection`, `HomeEditBar`, `startResize` as a mode. The HOM-12 tests that clicked "Remove from home: X" now select the item and use the bar's Remove (feature-grid `HomeEditModeTest`, `WidgetEditHandleW24Test`, app `EditChromeW45AppTest`). The scroll surface (Pages Continuous): a tap in edit mode selects (it launched the app before), icons and tiles get the outline, widgets get the flowing frame, and the bar is the remove path.

## Spec
HOM-07 and HOM-12 had three and four rows (one appended per stream); each is one row now (`docs/Spec.md`).

## Not matched / honest limits
- The widget sheet's presets go through the old reflow path (`HomeEdit.resizeWidget`), not the handles' "widgets block" rule: a preset that does not fit pushes neighbours like the grid's list does. Clamping to the provider limits is done; neighbours are not checked.
- Presets that are clamped to a size equal to the current one apply nothing and only show the note.
- The bar's `Resize` has no visual pulse on the handles; it focuses the frame (keyboard) and announces.
- On the scroll surface (Continuous) the handles are the flowing ones (east, south, south-east); a scroll item has no origin moves.
- The action bar in the page editor may sit over the small live card or the tabs; it only avoids the top bar.
- The live card is 0.45 of the window on 411x891 only with the panel at about 22 percent; on 320x568 it is about 0.39.
- Device only: touch feel of the handles next to the bar, TalkBack focus order between the bar and the handles, haptics, real insets, the page scale on a real window, gesture exclusion interplay at the screen edge.
