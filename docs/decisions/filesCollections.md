# Files collections, sorting and grouping (wave 53, HOM-15)

Owner request: "We have a files section which allows folders to be added, I want to also be able to add collections, like recents, or documents etc and sorting and grouping options."

## What a collection is
A saved query over the files the launcher can already see: the Radar file index (`FileIndexHolder`, filled by `FileIndexer` from the folders the owner granted, to a depth of eight levels and 20,000 files per folder, and from the media listing only when the system media permission was granted somewhere else). A collection is a name plus a `FileRule`: type groups (Documents, Images, Videos, Audio, Archives, Apps), an extension list, "name contains", granted folders, an age window ("changed in the last N days"), a size range. Every set criterion must hold; the type groups and the extension list count as one criterion (either fits). Pure code in `core-catalog` (`FileCollections.kt`), unit tested table-driven.

- **Nine ready-made collections**: Recents (changed in the last 30 days), Documents (PDF, Word, Excel, PowerPoint, text, ODF, ebooks), Images, Videos, Audio, Downloads (the file's own folder is called Download or Downloads), Archives, Screenshots (an image whose name contains Screenshot), Large files (100 MB and over; opens sorted by size, biggest first). A fresh install shows Recents, Documents, Images and Downloads; the owner switches any on or off.
- **Your own**: a "New collection" page with the same rule kinds, all as cards or short text fields. Save is the coloured box; Cancel and Delete are plain text below it; Delete asks first.
- **No new permission.** The Files section does not touch MediaStore and requests nothing. `READ_MEDIA_*` is declared but never requested today and this wave does not request it; if the owner grants it in system settings the Radar indexer already lists media, and collections (not All and not a folder) include those files. Without it, every collection is built from the granted folders only. The GrantGate explainer is therefore not used; the Add page's folder card opens the system picker, which is its own consent screen.

## The switcher and the chooser
- Chips: All, each shown collection, each granted folder, in that order, scrolling sideways with the selected chip kept in sight; the Add tile stays beside the row so it is never scrolled away. The last source is remembered. A removed collection or a folder whose grant is gone falls back to All without writing anything.
- All and a folder show the granted folders only (recursive through the index, which replaces the old "direct children, 20 per folder" listing; the files-per-folder chips of the Home panels settings are removed with it). A folder chip's "Open folder" action replaces the old tap on a folder row; long-pressing a folder to filter is replaced by selecting its chip.
- The Add tile opens a full-page chooser (a full-screen dialog): the nine built-ins as cards (glyph, name, example line, check when on), "New collection", the shown collections in order with Move up, Move down and Remove (a built-in is hidden, a custom one is deleted after a confirmation), the granted folders and "Add a folder" (system picker).

## Sorting and grouping
- Sort: Name (natural order, so file2 comes before file10; locale aware with the accent as a second-level difference; ties by the raw text and URI so the order is stable), Date modified (default, newest first), Date added (offered only when some file carries one: the folder grants and the index give no such date, so today it stays hidden), Size (unknown size is the smallest), Type (kind order, then extension). Ascending or descending.
- Group: None, Date (Today, Yesterday, This week, This month, Older, by the zone and first day of week of the device; a future date counts as today), Type, Folder (its own folder name; a file at the top of a granted folder uses the folder's name), Size band (over 1 GB, 100 MB to 1 GB, 1 to 100 MB, under 1 MB, unknown). Section order: dates newest first (oldest first when sorting a date ascending), types in kind order, folders by name, sizes biggest first with unknown last. Headers show the name and the count and are headings for the screen reader; sticky in the list, a pinned header over the grid.
- The control is a button in the header (sort glyph; description "Sort and group" and a state description such as "Date modified, Newest first, Grouped by Type"). It opens a bottom sheet of drawn cards. Changes apply at once. Done is the coloured box; below it plain text: "Use this for every source" (sets the global default and clears the per-source choices) and, only when the source has its own choice, "Reset this source to the default".
- Remembered per source (collection or folder) with a global default; Large files starts by size until the owner sets a default. The memory holds 200 sources and drops the oldest.

## Performance
The index is read on the IO pool, a fresh scan runs once per process (and when a granted folder has no listing yet) off the main thread with an "Updating..." note while the first read already shows; filtering, sorting and grouping run on the default pool; the arranged result keeps the first 2000 files after sorting and the header says "Showing the first N of M files". Rows and cells stay lazy and thumbnails keep loading per visible cell. Measured on the JVM: five arrangements of 20,000 files (every grouping) take well under the test's 8 s bound.

## Persistence
Collections (`panel.files.collections`), the global default (`panel.files.sort.default`), per-source options (`panel.files.sort.by`) and the last source (`panel.files.source`) are keys of `home_state`, read through TolerantPrefs. That file is in `StateLiveSources.ALLOWED` and not in `BACKUP_EXCLUDED_PREF_FILES`, so these choices are exported and backed up with the rest of Home. The folder grants stay on the device (the system holds them) and so does the file index (`palette-files.idx` is excluded from backup); a folder named in a rule or in a `f:` source id is meaningless on another device and simply matches nothing there (the editor shows it as "Folder not on this device"). No new classification entry was needed; `FilesCollectionsBackupW53Test` and `FilesCollectionsW53AuditTest` pin this.
