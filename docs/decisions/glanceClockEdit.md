# Glance clock edit mode (wave 50, stream w50-glanceClockEdit): decisions

Owner request (verbatim): "I want to be able to move and adjust the clock while on the calm glance screen. Long press on the clock should first afford the options to edit it, long press on an empty space affords the launcher config options."

## What changed

- **Long press ON the clock** enters an edit mode in place; **long press on empty Glance space** is the home's long-press action, unchanged (the quick sheet, or the bound LongPress gesture). The Glance top layer already hit-tests taps against the clock's bounds (a node with any pointer input would hide the gesture layer under it, see glanceClock.md), so the same layer now hit-tests the long press: `homeGestures` gets `isEmptyAt = !onClock(p)` (so a long press on the clock is not "empty") and the tap detector's `onLongPress` enters the edit mode when the press is on the clock. With the style Off there is no clock, so a long press anywhere is the config options.
- **The edit frame**: a 2 dp accent outline with a soft tint and four corner dots, drawn 10 dp OUTSIDE the clock (`drawBehind`, no layout change). While editing a tap on the clock does nothing (no clock app), a tap elsewhere does not wake the indicator, the long-press and swipe gestures are off, the home pager does not scroll, the page dots do not switch, and the fixed chrome (hotspots, music line) is dimmed to 40 percent and inert, the way the home editor does it (`EditChromeGeometry.FIXED_DIM`, `GlanceClockEditShield` swallows touch over the four corners and the music strip).
- **Drag**: the edit layer takes a drag that starts on the clock (grab area = the bounds plus 16 dp). The clock follows the finger, is clamped so it stays whole inside the safe area, snaps lightly (10 dp) to the vertical and horizontal centre lines with a haptic tick (the launcher haptic policy, `TextHandleMove`), and the place is stored on release (not per move step: one prefs write per drag).
- **Place model** (`ClockPlacement`, core-data): two fractions of the usable area (the window inside the safe insets): the clock's CENTRE x and its TOP y. Defaults 0.5 and 0.14, which is exactly where the clock always was, so nothing moves until the owner moves it. Stored per orientation (`glanceClockX`, `glanceClockY` portrait; `glanceClockXLand`, `glanceClockYLand` landscape) in `launcher_prefs`, so they survive rotation and other window sizes and travel with settings export and backup (the CFG-01 reflection test covers them). A broken stored value is the default. The clock is placed by a small `Layout` (`ClockPlacer`) that clamps to the area; the old top-centre padding is gone.
- **Options panel** (not modal, so the clock stays draggable): a rounded One UI card, on the far side of the clock (portrait: top or bottom, landscape: left or right, never covering it; it moves only when a drag ends). Rows: Clock style (a value row that opens the full radio page, the style list is not already outside), Clock size (Small, Medium, Large), Clock format (digital styles only), Show date under the clock, Clock colour (Automatic, Accent). Every option applies live. The actions are stacked: **Done** is the coloured box on top, **Reset position** and **Cancel** are plain text below (never side by side); one Done. The list scrolls under the pinned actions; the panel is at most half the height in portrait.
- **Cancel, Back and Esc** restore the snapshot taken on entry (style, format, date, colour, size and both orientations' places); **Done** keeps. **Reset position** returns the current orientation to the factory place (and keeps editing).
- **Accessibility**: the clock carries TalkBack custom actions at all times: Edit clock, Move clock up, down, left, right (a 5 percent step, clamped) and Larger clock, Smaller clock; moving by action needs no edit mode. While editing the node's state description is "Editing clock" and the panel is a pane titled "Edit clock". Keyboard and controller: Menu (or Shift+F10, or a secondary click) on the focused clock enters the edit mode (it is a `launcherItem` with `onMenu`); while editing, the arrow keys move the clock (a key handler on `LauncherInput`, Tab still walks the options), Esc is Cancel.

## Persisted state

New keys `glanceClockX`, `glanceClockY`, `glanceClockXLand`, `glanceClockYLand` (floats, 0..1) in `launcher_prefs`; same file, so StateSchema classification and the settings export/backup need no new entry (the CFG-01 test proves each is carried). Unknown or out-of-range values read back as the default.

## Not matched / device only

- The drag feel, the haptic tick on the centre lines, TalkBack custom-action rotor, a hardware keyboard Menu key and the look over live wallpapers are device checks.
- The panel is at most half the portrait height, so on a short phone the Date and Colour rows are below the fold of its scroll area (the actions stay pinned); on a very small window the panel can still cover part of a Large clock (drag it, or use Small).
- The edge swipe that opens Launchpad or Recents is not blocked while editing (only the page dots, the pager and the fixed chrome are).
- A drag cannot start on a part of the clock that lies under the panel; the panel jumps to the other side when a drag ends with the clock past the middle.
- Per-orientation places are independent; there is no "same in both" switch.
