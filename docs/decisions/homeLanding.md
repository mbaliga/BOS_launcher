# Home landing (HOM-22): decisions

Owner request: a home that can land on recent apps, with Selected apps, Recent apps, All apps and Minimal (the wallpaper and the four hotspots).

## The setting
- `LauncherPrefs.homeLanding` (`HomeLanding`: Selected, Recents, AllApps, Minimal), stored as a plain pref `homeLanding` in `launcher_prefs`. It is exported with the settings and not device-bound. An unknown or missing value reads as Selected, so an older export imports unchanged.
- Also stored: `recentsLimit` (8 to 48, default 24), `recentsUsage` (use usage access when granted, default on), `minimalHints` (the dot per hotspot, default on; removed in wave 20, see the glance record).
- Global, not per workspace: the workspace model keeps only an opaque `homeArrangement` snapshot and no home settings, so a landing per workspace would be a new model. Revisit if workspaces gain home settings.
- Switching changes only this pref. Pages, folders, widgets, tags and hidden apps are never rewritten.
- Default stays Selected apps. Making Recents the default is a one-line change (`LauncherPrefs.homeLanding` default) and an owner choice. The empty-home hint gains "Or show recent apps" in the UI step.

## Recent apps
- Sources: Liftoff's own launches (the timeline log, up to 5000, already private) and, with usage access, UsageStatsManager foreground events (`UsageRecents.sightings`, public `queryEvents`, 7 day window). No `getRecentTasks`, no reflection, no hidden API: the platform has no public live-task list.
- Rules are one pure function (`HomeRecents.compute`): newest first, one entry per app key, bounded by the limit, hidden apps and Liftoff itself excluded, uninstalled apps dropped, work profile kept (optional profile filter, the UI badges work apps). A usage sighting names a package; it resolves to the installed entry Liftoff launched most recently, else the personal entry. UsageStatsManager only reports the calling profile, so work apps appear from Liftoff's own history.
- Running app first: a Liftoff-launched app still in a session moves to the front only if it is already in the list; it never adds an app and never reorders the others. Without usage access this is the one case where "newest" and "current" differ.
- Remove and clear: `RecentsState(clearedAt, removedAt)`. An event hides when it is at or before the clear time, or at or before that app's removal time, so launching the app again brings it back. Stored in `files/usage/recents-state.txt` (bounded to 200 removals), read and written on an IO executor. The file is in `NEVER_EXPORTED_FILES` and under the `usage` directory that backup rules already exclude.
- The list is a `Flow` combining history, usage sightings, apps, hidden set, removals, limit and profile; it runs on `Dispatchers.Default` and emits only on change. Usage events are re-read when the caller ticks (home resume, grant).

## Minimal
- `MinimalHotspots.effective(corners)`: a corner on the factory assignment gets Radar, Launchpad, drawer, Ground Control (top-left, top-right, bottom-left, bottom-right); an assigned corner (including an explicit Nothing) is kept. Nothing is written, so leaving Minimal restores the previous look. Ground Control was chosen over a quick-sheet action for the bottom-right corner because the wallpaper long press already opens the quick sheet.
- New corner actions `OpenLaunchpad` and `CycleLanding` (both internal) so the defaults and the cycle are assignable to corners and gestures. The factory corner assignment (Camera, Music, Radar, drawer) is unchanged for the other landings.

## Rules per landing (`HomeLandingRules`)
Edit mode, pages and the empty-home hint belong to Selected apps. Recents and All apps use the chosen home style without pages. All apps has the alphabet index, type-to-filter and profile tabs. Minimal draws no chrome. Long press opens edit mode on Selected apps and the quick sheet elsewhere; "Edit home pages" switches to Selected first.

## Command
`LauncherCommand.CycleLanding` ("Cycle home landing"), default Ctrl+Shift+L, not a global shortcut. Cycle order: Selected, Recents, All apps, Minimal.

## The surfaces (step 2)
- One switch in `HomeScreen`: a `Crossfade` over the landing wraps the existing home. The Selected branch is the old `when (homeStyle)` untouched; the other landings are the new composables in `feature-grid` (`HomeLandingScreens.kt`, `HomeLandingUi.kt`). The cross-fade is 220 ms and falls back to the short reduced-motion fade (`MotionPrefs.crossFadeMs`).
- **Recent apps**: `RecentsLanding` draws the bounded newest-first list in the chosen style. Grid and DSi use the continuous grid (the "icons across" setting, three across for DSi) in the given order; the list style uses a new newest-first list (`RecentsListHome`, the existing list home sorts A to Z); the cross media bar gets the list as its apps and as its Recent column. The paged grid has no pages here, so it uses the continuous grid. Long press, right-click and the Menu key reach one callback that opens the app menu with "Remove from recents" and "Clear recents" added. The live list is only collected while this landing is on (`rememberRecentApps`). "Running app first" is not wired: the newest launch is already first, so it could only repeat the order.
- **Empty state**: one quiet line, one line saying apps opened from Liftoff appear here, and, only while usage access is off, how to include apps opened elsewhere with an "Allow usage access" button that goes through the existing grant explanation (CFG-07).
- **All apps**: `AllAppsLanding` reuses the drawer's own filter bar (tabs, work pause chip, tags, type-to-filter) and filter rules, sorted A to Z, in the chosen style. The list style keeps its own letter rail; the grid and DSi styles get a new `LetterIndexRail` (drag to jump, each letter a button) driven by a `ScrollJump` request added to `ContinuousHome`. The cross media bar groups by category and has no alphabet to jump along, so it has no index (type-to-filter still works).
- **Minimal**: `MinimalHotspotLayer` draws nothing but the four hotspots (64 dp touch targets at the physical corners, one faint dot each when "Show corner dots" is on). Each is a focus-graph node (`minimal.corner.*`), a labelled button for TalkBack ("Top left hotspot: Radar") and runs on click or Enter. The pointer dwell reveal and the four corner shortcuts are the shared hot-corner layer and commands, fed with the Minimal assignments. A palette assignment runs its first item (there is no room to fan out); a complication, a widget or nothing is not a hotspot. The wallpaper, the scrim and the indicator effects stay; the strip, dock, media strip, Launchpad rail and handle, work chip, page dots and tiles are not drawn. The edge swipes and the gesture layer (swipes, pinch, double tap, long press) still work. Bottom-left runs "All apps": the drawer, or the puck when the drawer style is the puck (the existing rule).
- **Switching**: Ground Control > Home gets the "Home landing" row at the top (a list of four rows, a glyph, the name and the one-line description each; the Recent apps count and the usage-access switch appear only while Recent apps is on, the dot switch only on Minimal). The quick sheet has a four-way segmented control under its title. The cycle command, corner action and gesture action show a toast naming the new landing.
- **Edit mode**: only on Selected apps. A long press on empty space opens the quick sheet on the others (a bound LongPress gesture still wins, as everywhere); the quick sheet's "Edit home pages" switches to Selected apps and enters edit mode; leaving Selected ends an open edit session.
- **Hint**: the empty Selected home shows "Long press to add apps" and a second line "Or show recent apps" that switches the landing.
