# Pages are explicit (wave 30, HOM-01, HOM-12, HOM-22)

Owner, build 59 (the Glance showed the house and 14 page dots): "Don't show all the pages at once with all the icons, add one page at a time, empty, and let the user add their icons and widgets to it by themselves - you are showing all the pages with all the icons and the pages don't even get deleted - not okay."

## Why it happened (reproduced in JVM tests before the change)
- `HomeLayoutMath.visualPages` appended every installed app that was not on a page to the LAST page and chunked it by capacity (the "All apps" default of the old `appsOnHome` pref, kept for every install that predates the pref). So an existing install drew ceil(apps / capacity) full pages whatever the user had built. The first edit of any kind (`savePages` writes the visual list) then stored that auto-filled arrangement as if the user had made it, which is why 14 pages stayed after the pref was changed.
- `HomePageOps.delete` / `HomeLayoutMath.deletePage` moved the deleted page's items to the end of the previous page, and the auto-place step would have put them there anyway: a delete looked like it did nothing.
- `HomeLayoutMath.cascade` (used by `add`, `move`) opened a new page whenever the target was full, and `finish` dropped a page when its last item moved away, so pages appeared and vanished without the user asking.
- `AddCarouselModel.place` put the item on the first page with room or grew a page; a first-run effect also placed Settings, Phone and Messages on an empty "only the ones I add" home.

## The model
1. **Pages are explicit.** A page exists because the user added it (edit card Add page, the quick sheet, Ground Control Add page, the Pages setting turning the first page on) or because the install starts with one. Each Add page adds exactly ONE empty page after the current one (`HomeDeck.addPage`, `HomePageOps.add`); it never copies and never fills. The indicator counts the real pages: the house plus one dot per page.
2. **Icons and widgets are explicit.** `visualPages` never places an app. Newly installed apps are in the drawer and Radar only. The only thing it still appends is the user's OWN non-app items (folders, widgets, shortcuts, links) that another window size class's arrangement lacks (the `strays` parameter, `HomeResolve.visual`), so a widget made in portrait is not missing in landscape; deleting the item removes its definition, so it cannot come back. The first-run seed of three apps is deleted. `appsOnHome` is no longer read for placement; the Ground Control row is removed and the migration sets it to "Only ones I add" (the stored enum stays so old settings files import).
3. **Overflow of explicit items.** DECISION: a full page says "Page full. Add a page or remove an item." and nothing else happens. Tapping an app in the add carousel, adding a widget, shortcut, link or group, or dropping on a full page does not spill onto another page and does not open a page (`AddCarouselModel.place` returns null, `HomeLayoutMath.add` and `move` return the pages unchanged, `HomeEdit.add` returns the state unchanged, `HomeItems` shows the toast). The one place a page can still continue onto a second visual page is a DENSITY change that shrinks the grid (`setLayout`): those chunks share the stored page id, merge back on save and are one page to the user (deleting any chunk deletes the whole page). A drop onto the "new page" slot past the last page is an explicit Add page and stays.
4. **A page is only removed by the user.** Moving or removing the last item of a page leaves the empty page (`finish` no longer drops it).
5. **Delete page works.** `HomeLayoutMath.deletePage` / `HomePageOps.delete` remove the page and every placement on it; nothing joins a neighbour. The edit card carousel, the quick sheet (with 2 or more pages), the page's Settings row and the long-press sheet all go through `deletePageNow`. A page that holds something first asks: "N items will be removed from this page. They stay in the drawer." (`PageDeleteConfirm`); an empty page goes at once. Apps leave the home and stay in the drawer; folders, widgets, shortcuts and links are removed the usual way, so edit mode's Undo (the existing undo stack, one tap) restores the page and its items. The last page is emptied, not removed: DECISION: deleting the last page leaves Pages on with one empty page; turning Pages Off is a setting. The current page index moves to the previous page, the indicator and Continuous mode follow the stored page list.

## Migration (one time, JVM-tested with fixtures; `PagesExplicit`, `PagesExplicitMigration`)
- Runs at the first start of this version once the app list is known and the fresh-install decision is made; the store remembers it (`pagesExplicitVersion`).
- A layout is the legacy auto-fill when it has no recorded manual edit (`explicitEdit`, set by every user edit path from now on: `setPages`, `removeFromHome`, `addToHome`, the add carousel, delete page, Restore) and any of: (1) at least two non-empty pages made only of at least 12 installed apps, every page but the last full (as full as the fullest stored page, so a density change since the auto-fill does not hide it), in an automatic order (catalog or alphabetical); (2) MORE than 4 consecutive full pages whose apps cover MORE than 60 percent of the installed apps; (3) the old "All apps" mode with at least 3 non-empty pages covering at least half of the installed apps.
- A reset keeps the old arrangement in `files/home_layout_legacy.json` (classified in `StateSchema.BACKUP_EXCLUDED_FILES`, excluded from backup and device transfer in both XML files), leaves ONE empty page with the Pages mode untouched, forgets the other size classes' stored copies (they were seeded from the auto-filled one), and shows the one-time dialog "Home pages were reset: they held every app automatically. Add your own in Edit home." with the action "Restore previous pages". The same action is a row in Ground Control, Home screen, for 30 days. A backup that cannot be written leaves the layout alone and the migration pending; the notice is dropped when its backup file is gone (it is excluded from backup and transfer, the flag is not); restoring over pages the user built since asks first. A restore puts the old pages back and marks the layout as the user's own so it is never reset again.
- A layout the user built (2 pages, small counts, any recorded edit) is kept untouched and marked done. A fresh install and an empty catalog decide nothing.

## Not done / device only
- Nothing is device-confirmed. Robolectric drives the real UI for Add page, placing an app and a tile, an install, delete with confirmation and Undo, the reset notice and Restore. The widget of the owner's script is stood in for by a home tile because there is no widget host under Robolectric.
- The automatic density-increase reflow (pulling icons forward when the grid gets bigger, and the "Fill the empty space?" prompt) is kept: it only rearranges explicit items on a user's density change.
- `LauncherPrefs.appsOnHome` and `HomeLayout.removed` remain as stored fields (old settings files and exports carry them); neither places anything any more.
