# Panel widgets (wave 52): Widgets, the fifth section of the Comms panel

Owner: "I would also like to be able to add widgets to it (as a fifth section) where I can add widgets instead of on the right side, if I so choose."

## Decisions
- The panel's tab row was ALL UNREAD FILES TIMELINE (Read history has no tab). Widgets is the fifth tab (`HubView.Widgets`, id `widgets`). It exists only while the setting is on (Settings, Comms, "Widgets section", default off), so nothing changes until the owner chooses. Turning it off while it is shown falls back to All; a `liftoff-panel://widgets` link and the Default view choice ignore it while it is off.
- "Where": a visual card choice, "Widgets position": Last (the default, the owner's fifth), First, or Before Files. Only these three; the order of the other four never changes. `PanelSections.order` is the single place that says the order (tested); the mock-up's tab slot widths stay with their own tabs wherever they sit.
- Hosting is reused, not copied: the app body (`PanelWidgetsBody`) uses the home's process-wide `LauncherWidgetHost` (counted listening, started with the activity and only while this section is composed, which is only while it is the shown tab of an open panel), `rememberWidgetPicker` (the existing picker dialog with the bind consent and the provider's configure screen; the page editor's browse carousel is not in this branch), and `HostedWidget`. Two small public helpers were added next to the picker (`reconfigureWidget`, `canReconfigureWidget`, over the host's public configure call) for Widget settings.
- Module boundary: `feature-launchpad` has no dependency on `feature-grid`, so the section is drawn in the panel's module against a small seam (`PanelWidgetsApi`: availability, height, configure, add, release, focus node, render); the app fills it with the real host and `launcherItem`.
- Persistence: ids and labels in the existing device-local pref file `launchpad_hub` (`widgets`, `widgetsSection`, `widgetsSlot`), which is already classified as backup-excluded and never exported; widget ids belong to this device's host, so they are not portable (the home's import re-add flow does not cover this section). Host ids survive a restart and a provider update; a provider that disappears gives an "unavailable" card with a Remove button (looked up again each time the panel resumes). Safe mode (crash-loop guard) shows the cards as unavailable instead of hosting.
- Cards: full width (capped at 640 dp in landscape), height from the provider's minimum height, raised to its minimum resize height and capped by its maximum resize height, between 72 and 360 dp. No drag handle: reordering is Move up and Move down (menu and TalkBack actions), removal is Remove (no confirmation, the widget can be added again). A long press (observed without consuming, so the widget still gets its touches), the options button, Menu or Enter open the menu.
- Not done: no resize handles (the provider's size decides), no drag reordering, no backup of the list, no widget stacks.
