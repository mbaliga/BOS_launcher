# Puck sections: four wedge sections around a Back hub (wave 30)

Source: the owner, with two annotated screenshots (our disc with the five round shortcut buttons ringed; the Concepts quick switcher with its wedge sections ringed): "The shortcut icons that I have marked should show as sections, just like the sections marked in the concepts app. And the centre button should become a back button instead of search. The user should be able to configure the shortcuts to be shown in the four sections."

## Decisions
- **Sections.** The ring of round buttons is replaced by exactly four wedge sections, a quarter ring just outside the hub's centre button and just inside the grouping labels (`PuckSections.kt`, pure geometry in `PuckSectionsGeometry.kt`). Contiguous wedges of the visible quadrant with a 1 dp gap (an angular gap that is 1 dp wide at the mid radius), filled with the theme surface (a step lighter than the hub), the glyph centred and upright, no label by default (the label is the content description and the long-press name). A pressed wedge goes dark with an accent arc along its outer edge, as the selected wedge of Concepts. Slot 1 sits next to the screen's horizontal edge (the thumb's side) and slot 4 next to the vertical edge in all four corners; the other hand's corner is the exact mirror (`PuckSectionsGeometryTest`). The drawer lays out left to right whatever the locale, so a right-to-left language does not reorder the physical wedges.
- **Touch.** Each wedge is its own node: a transparent box over the wedge's bounding box clipped to the wedge shape, so the tap area is exactly the wedge and neighbours do not steal taps. Tap runs the shortcut, long press shows its name in a small pill (and does not run it), haptics through `rememberLauncherHaptics`. An empty slot is a faint wedge with no glyph; tapping does nothing, a long press opens Ground Control on App drawer (`CATEGORY_APP_DRAWER`) where the editor is. An action the device cannot run (no flashlight, no Do not disturb access) is dimmed with the state description "Not available on this device"; the tap still runs the action, which explains itself with its toast or the access screen, as the old buttons did.
- **48 dp.** The Back button is at least 48 dp across (hub radius 24 to 34 dp). The ring is at least 48 dp deep (radial) whenever the window is 300 dp or more across. Across the arc a wedge is narrower (about 25 to 38 dp at mid radius on a phone) because four wedges share a quarter turn; making that 48 dp would need a hub radius over 120 dp, so it cannot be met without hiding the apps. The wedge fills its whole tap area (the gap belongs to the nearest wedge in `PuckSectionsGeometry.hit`) so the effective target is the whole wedge. Documented gap, not a bug.
- **Centre button is Back.** A black round hub with a left arrow closes the drawer exactly like the system Back (`onDismiss`). The search glyph is gone from the hub; search stays reachable through the Radar glyph on the home, the chord, the gesture, the `/` key on the open disc and the Radar shortcut that can be put into any section. Back is first in the traversal order (index 0, focus node `puck.back`), then the sections (1 to 4, `puck.section.N`), then the bands; Enter and Space activate the focused one.
- **Configurable slots.** `PuckActions` is now four slots (`PuckSlot`: `Empty`, `Action(id)`, `App(key)`). The choosable actions are every `CornerActionId` except `AllApps` (the disc itself), with Radar (`Search`) added. Radar scope shortcuts do not exist in the action list, so there are none to offer. Settings: Ground Control > Home screen > App drawer > Drawer shortcuts (`PuckActionsPane.kt`): four rows (1 to 4), each opening a list of Empty, App... (the app picker) and the actions; Reset to default. The old multi-select UI (move up/down, remove, add, "fits N of 9") and its strings are gone; the separate "Puck" settings category (which the reorganised Ground Control never showed) is gone.
- **Defaults and migration** (`PuckActions.migrate`, JVM tested): a fresh install, and anyone with nothing saved, gets flashlight, alarm clock, bell (Notifications) and Do not disturb. A wave 29 install with a saved ring keeps the first four actions in order; a ring shorter than four is completed with the defaults not already in it; an emptied ring gives the defaults. Radar and All apps in an old list were never allowed and are dropped.
- **Storage.** The `puck_actions` file (already exported, `StateLiveSources.ALLOWED`, `W13CrossAuditTest`) holds the new `slots` key (one slot per line: `-`, `a:<Action>`, `p:<app key>`). The wave 29 `actions` key is read once by the store, migrated and removed in the same edit (so an old export imported later is migrated the same way; `StateReload` calls `reload()`), which is why it is not in `RetiredPrefKeys` (that purge would run before a late import).
- **Left alone.** `PuckLayout.compute`'s ring slots and capacity in core-input are no longer used by the disc (only the hub and label radii are); the function and its tests stay for now, the drawerLoop stream edits the same files.
