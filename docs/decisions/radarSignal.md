# Radar background: signal source and signal views (PAL-24)

## Decisions

1. **No telephony listener.** `TelephonyCallback.SignalStrengthsListener` is not used. Its permission requirement could not be confirmed from the SDK in this environment (no SDK sources or javadoc are available offline, and `android.jar` carries no permission annotations), and the platform documents `READ_PHONE_STATE` for parts of the telephony callback family. The rule for this stream is: if it needs `READ_PHONE_STATE`, do not use it and ask the owner. So the signal comes only from `ConnectivityManager.registerDefaultNetworkCallback` and `NetworkCapabilities` (`TRANSPORT_WIFI`, `TRANSPORT_CELLULAR`, `TRANSPORT_ETHERNET`, `NET_CAPABILITY_VALIDATED`, `NET_CAPABILITY_INTERNET`, `getSignalStrength()` on API 29+), which need `ACCESS_NETWORK_STATE` only (already in the manifest). **Question for the owner:** is a finer cellular bar count worth asking for `READ_PHONE_STATE`? The answer decides whether the cellular level may use `SignalStrength.getLevel()`. Until then cellular uses the dBm the capabilities report.
2. **Normalisation** (`SignalLogic.normalise`, pure, tested): no network = level 0 (kind None). Wi-Fi RSSI: >= -55 dBm excellent (4), >= -65 good (3), >= -75 fair (2), else weak (1). Cellular: >= -85 / -95 / -105 dBm for 4 / 3 / 2, else 1. Strength not reported (`Int.MIN_VALUE`): connected Wi-Fi or cellular reads 3, wired 4. A network the system could not validate (captive portal, no internet) is capped at weak (1) and keeps `validated = false`; it is not "no signal", so the comic lines stay off for it.
3. **Debounce 600 ms** (first value immediate, repeats dropped, a change must hold for the window), applied on the flow so a flicker never reaches the screen. The pure twin `SignalLogic.settle` is what the tests exercise.
4. **Collection**: only while Radar is composed and the activity is started (`repeatOnLifecycle(STARTED)`), only when a signal view or the comic lines are on, and the callback is delivered off the main thread. The source is an interface (`SignalSource`); tests inject `FixedSignalSource`. No traffic of our own: nothing is requested from the network, so NFR-16 and NFR-17 audits are unaffected.
5. **Comic lines are independent of the signal view.** The comic switch decides them alone: with the view Off and no signal the lines still show (they are the no-signal indicator). With the switch off, no signal shows only the resting grey lines and no pulses.
6. **The dot's peak alpha is 0.255, not 0.30.** The owner's SVG uses a 30 percent white fill seen through a #D9D9D9 dot mask, which is 0.30 x 0.85. This is also what lets the layers on top stay under AA contrast with the result text (NFR-15; the measured worst case in the render test is about 4.9:1 on the dark Radar and 8:1 on the light one).
7. **Light Radar.** The painters take `dark`; the light variant (dark ink on light, fainter) is built and tested, and `RadarBackgroundHost(dark = ...)` carries it. Radar's own backdrop is still black in every theme, so the host passes `dark = true` today. Wiring a light Radar surface is a one-line change when that surface exists.
8. **Frame clock.** One infinite transition (`rememberInfiniteTransition`, 3600 s linear, read in draw lambdas as milliseconds) shared by every layer. It exists only while the activity is resumed and the window has focus, and never under reduced motion, so nothing animates while Radar is closed, the screen is off or the window is unfocused. A first version used a hand-written `withFrameMillis` loop; it kept Compose test clocks from going idle (the public API has no test-aware variant of it), so the infinite transition, which tests can stop, replaced it. The clock reads `rememberMotionPrefs()` (NFR-14 audit).
9. **Glow geometry.** The eight outline shapes are parsed twice, once into Compose paths by `PathParser` (the resting grey shapes, drawn through one transform and an elliptical gradient so the middle stays calm) and once by a small pure flattener into centre lines (midpoints of matching positions on the two edges of the tapering outline). Pulses are slices of the centre lines traced into one reused path and stroked three times (11, 5 and 2 dp, alpha 0.09, 0.15, 0.25 at full level) so a glow costs three strokes and no blur or RenderEffect (NFR-05). Landscape stretches the artboard to the window; portrait transposes it (the design is symmetric), as the dot grid does.

## Pluggable views

`SignalView` (id, label, `prepare(geometry)` giving a `SignalPainter`) and `SignalViews.views`. A new way to view signal is one class and one entry in that list; the setting stores the id, an unknown id falls back to Glow lines, "off" is built in.
