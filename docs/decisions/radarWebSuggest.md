# Radar web results (wave 43): Enter opens the engine, live suggestions, Play Store rows

Owner report (verbatim): "If I search the web, I should start seeing search results here. Even when I go to search the web, pressing send/enter/go opens play store. When searching apps, show play store results as well." A screenshot showed Radar on the scope THE WEB with the query "spider" and empty rings.

## 1. Why Enter opened the Play Store (root cause)

`SearchData.tilesFor(Web)` listed the Play Store lookup row before the engine's search row ("any hits first, then the app-store lookup, and the hand-off to the browser last", PAL-06/PAL-15 of wave 18/25), and Enter (`SearchData.enterTile`, the IME Go action and the hardware Enter) runs the first tile of the selected scope. So on the Web scope, and on Everything when no app matched, the first tile was "Search Play Store for ...". The engine setting was not involved: `WebEngine` mapped correctly, `submitSearch` (the fallback) already put the engine first. The rings were empty because every web row is a "strip tile" (`isStripTile`): in the typed Orbit they go to the bottom strip as three icon circles with no caption, never to the rings.

Fix: the Play Store row is no longer a web row. It belongs to the Apps results (see 3). In the Web scope Enter is always the first `Tile.Web` that is not the store (the engine's search row, or a URL's own "Open" row), and never a suggestion, an answer or a store row. Regression tests per scope: `RadarWebW43UiTest` (`enterTile` for Web, Everything with and without an app match, Apps with and without a match, a URL, Web results off; and the real IME Go on Web, Everything and Apps).

Default engine: new installs default to Google (it was DuckDuckGo); an install that already stored DuckDuckGo keeps it. Ecosia added (results page only, no suggestion endpoint). Startpage has none either. There is no "Custom URL" engine in the app, so none was added.

## 2. Live web results (the only network use of the launcher)

- Setting: Ground Control > Radar > **Web suggestions** (On / Off, default **On** because the owner asked for live results). It is a new switch, not the old "Web results" row: that row (`searchWeb`) hides the whole web hand-off (search row, Play Store row, Enter fallback) and has always meant "show web rows"; reusing it would make "Off" remove the search row, which the owner's wording ("Off = only the single search row") rules out. Nothing to migrate: both keep their stored values; a missing `webSuggestions` key means On.
- Sent when the scope is The web (to the chosen engine's suggestion endpoint) and in Everything (the same, and the Play Store endpoint) unless a contact matched the text; in the Apps scope only to the Play Store endpoint. Never sent: text under 2 or over 100 characters, a URL, an email address, a phone number; with Web suggestions Off or Web results Off.
- Endpoints (public, unauthenticated; they can change or refuse, none was called from this machine): Google `suggestqueries.google.com/complete/search?client=firefox&q=`, DuckDuckGo `duckduckgo.com/ac/?q=&type=list` and the instant answer `api.duckduckgo.com/?q=&format=json&no_html=1&skip_disambig=1`, Bing `api.bing.com/osjson.aspx?query=`, Brave `search.brave.com/api/suggest?q=`, Play Store `market.android.com/suggest/SuggRequest?json=1&query=&hl=en&gl=us&c=3` (fixed language and country). Ecosia and Startpage: none, so only the single search row.
- Client: `WebSuggest.kt` (pure: rules, URL builders, parsers, debounce, cache) and `WebSuggestHttp.kt` (the one class with `HttpURLConnection`): HTTPS only, GET, own short-lived background thread, 800 ms debounce after the last keystroke (the Compose effect restarts on each keystroke, which cancels the wait and aborts a request in flight; leaving Radar cancels too), 2 s connect and 2 s read timeout, 64 KB response cap, redirects not followed, no cookie handler and no Cookie header, generic User-Agent, no other identifiers. Only the typed text is in the request. Cache: last 30 queries, in memory, case-insensitive, never written to disk. Failure or offline: silently empty (a failed fetch is not cached).
- Rows: the Search row on top (Enter), the DuckDuckGo answer card (heading and text, tap opens the source page; the answer image is not fetched), then up to 8 suggestions (tap opens the engine's results for it). In Everything: after the app matches, the search row, up to 3 suggestions, then the Play Store group. They are `HitKind.WebAnswer` / `WebSuggestion` / `PlayStore` hits and appear as list rows, Filmstrip tiles and Orbit ring tiles. They are never learned (no `PaletteHost.learn`), never stored.
- First-use note: the first time suggestions load in the Web scope, one line "Suggestions come from <engine>. Turn off in settings." shows under the results; shown once (flag `webNoteSeen` in the `radar_ui` pref file, already classified).
- Permission: `android.permission.INTERNET` (normal, no prompt) is declared again; location is not. Audits (`PrivacyAuditTest`, `W4MotionAuditTest`, `DeviceKitAuditTest`) now pin: exactly one source file (`WebSuggestHttp.kt`) contains a connection class, it is HTTPS-only, the permission appears once in the app manifest only, no other network-like permission, no cleartext opt-in, no network library in any build file.

## 3. Play Store results when searching apps

The Apps scope and Everything list the installed matches first, then a "Play Store" group (green Play glyph tile and a "Play Store" label, so it is never mistaken for an installed app): the row "Search the Play Store for “<query>”" (2+ characters, no network, always shown while Web results is on; `market://search?q=&c=apps`, or the store's web page when no store app is visible) and, with Web suggestions on, up to 8 store app suggestions (2 in Everything) that open the same market link. In the Apps scope Enter launches the top installed match, else the Play Store row.

## Privacy, stated plainly

With Web suggestions on, text typed in Radar's Web scope goes to the chosen search engine (Google by default) while you type, after a pause, before you press anything; text typed in the Apps scope goes to Google Play's suggestion service; Everything does both unless a contact matches. The engines see your IP address and the text (and whatever their own servers log); the app sends no identifier, cookie, locale or history. Off means no network at all from the launcher. Apps and people you search for by name in Everything or Apps are sent to Google Play's suggestion service when typed: turn the switch off if that is not acceptable.

## Not verified here

Whether each endpoint still answers in the documented shape, rate limits, and the look on a device are unverified.
