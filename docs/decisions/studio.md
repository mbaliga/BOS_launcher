# Liftoff Studio: a browser editor for the Settings export (wave 56)

Owner: "Browser page will be good, and it should be like in the asystemofcells/liftoff/studio". The study that raised it is [../handoff/clackpad_vs_liftoff_settings.md](../handoff/clackpad_vs_liftoff_settings.md) (Q3: Clackpad's Studio is a left-preview, right-tabs page over one shared file format). Nothing here was run on a device or on the owner's site.

> Wave 58: the tab and group of each field now come from the app's Settings layout, the page has a phone Profiles panel, and the drawing gained Signal approximations, landscape and side docks: see [studioPreview.md](studioPreview.md).

## Decisions
- **Self-contained static site in this repository**, `web/liftoff-studio/`: `index.html`, `studio.css`, `app.js` (the page), `core.js` (logic, no DOM, testable under node), `preview.js` (SVG drawing of the phone), `cards.js` (option card drawings), `schema.json` / `schema.js`, `fonts/`. Vanilla JS and CSS, no build step, no CDN, no network request of any kind (a test greps for `fetch`, XHR, beacons, sockets and external addresses). Every URL is relative, so the folder works from any sub-path and from `file://`.
- **The site repository was not accessible**, so nothing could be put on the owner's site. The folder is built so that publishing is a copy (below). An optional workflow, `.github/workflows/liftoff-studio-pages.yml`, can publish it on GitHub Pages; it is `workflow_dispatch` only and does nothing until Pages is enabled.
- **One file format with the app.** Studio reads and writes the documents the app already has: `liftoff-settings` (the "Export settings only" file) and a partial `liftoff-state` Backup (settings, `dock.settings`, `shortcuts.corners` and `shortcuts.gestures`, and the allow-listed pref files `comms_scale`, `launcher_haptics` and `puck_actions`). A partial Backup holds only these sections, and the app's import writes only the sections present, so the layout, groups and workspaces on the phone are untouched. A full Backup imported into Studio is carried through unchanged except for those parts. No second format, so no drift (the lesson of Clackpad's two builders).
- **The schema is generated from the code, not remembered.** `core-data/.../StudioSchemaW56Test.kt` builds `schema.json` and `schema.js` from `LauncherPrefs`, `SettingsCodec.encode` (every key the export carries, with the default install's value), the enum entries and ids, `StateSchema.DEVICE_BOUND_PREF_KEYS`, `PrefFilesSource.ALLOWED`, the constants the settings sliders use, and the dock source (`DockSettings` fields and the `DockMode` and `DockEdge` entries, read as text because `feature-dock` is not a dependency of `core-data`). Only labels, tabs, groups, the preview scene and the "show when" rules are editorial. The test fails when an exported key is missing from the schema, when a schema key is not a real key (or a device-bound key lacks its flag), when a default or option id changed, when the two generated files are stale, and when the app's own decoder does not read the files Studio writes. `STUDIO_REGEN=1` rewrites the files.
- **Six tabs** as the owner asked for Settings: HOME (Glance, clock, pages and grid, corners and hotspots, gestures, keyboard, motion, dock), LOOK (theme, icons, font, wallpaper, signal and battery, backdrop), APPS (drawer disc, home apps, badges; workspaces and groups are phone-only), RADAR, SIDE PANEL (Comms, Recents panel or dock rail), SYSTEM (language, sound and vibration, screen, what stays on the phone, Backup and access notes). The tab assignment is one table in the test; if the app's reorganised Settings places a field elsewhere, change it there and regenerate.
- **Device-bound and unknown.** `onboardingDone`, `leftWidgetId` and the wallpaper picture files are flagged `deviceBound`: never exported, dropped from an import with a note. Fields Studio does not know (a newer build's, or retired keys) are kept in the profile and written back. Wrong types are refused with a message naming the setting; out-of-range numbers are clamped with a warning (the app clamps too); an option name Studio does not know is kept with a warning.
- **Corners, gestures, ring shortcuts** are edited only when they hold a built-in action (or nothing). A corner, gesture or ring segment that holds an app, a palette or a widget shows "Custom (kept)" and is written back as it was.
- **Profiles** (New, Duplicate, Rename, Delete, Use, plus quick looks Midnight, Paper, Terminal, Sunset and starter profiles Work, Calm, Desk) live in the browser's `localStorage` (a failed or blocked storage is reported and the page still works). There is no "Looks" list in the app on this branch, so the four looks are Studio's own. Share link: the values that differ from the defaults, JSON in base64url, in the URL fragment, at most 6000 characters; a link is read with the same checks as a file.
- **Preview**: SVG built by pure functions (`preview.js`), switching to the area the active tab or field concerns (field `scene` in the schema; a "follow" switch turns that off). The fonts are the app's OFL files, copied with their licence texts.

## Publishing at `<site>/liftoff/studio/`
1. Copy the folder: `rsync -a --exclude tests --exclude README.md web/liftoff-studio/ <site-checkout>/liftoff/studio/` so `liftoff/studio/index.html` exists.
2. Serve static files (`.ttf` as `font/ttf`); make `/liftoff/studio` redirect to `/liftoff/studio/`.
3. Open it and check that the phone draws and the tabs switch.
Optional, GitHub Pages of this repository: enable Pages (source GitHub Actions) and start "Publish Liftoff Studio" by hand; it serves `<pages-root>/liftoff/studio/`.
Remaining for the site: someone with access to the site repository does steps 1 to 3, and (later, another agent) the app gets an "Open Studio" link in Backup.

## What it does not cover, and how to undo
The preview is a drawing from the settings: Signal, System and Picture wallpapers are placeholders, text and apps are samples, portrait only, the Word clock shows one time, the adaptive grid and Glance spacing follow the app's rules approximately, no motion, sound or haptics, no side dock (landscape). The file Studio writes was checked against the app's JVM codec, never imported on a device. To undo: delete `web/liftoff-studio/`, the workflow, the test and the three doc rows; nothing in the app depends on them.
