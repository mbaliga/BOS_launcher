# studioPreview (wave 58, CFG-70 to CFG-74): Studio follows the app's tabs, edits phone profiles, and both previews close their gaps

Follow-up of [studio.md](studio.md) (wave 56), [settingsTabs.md](settingsTabs.md), [profiles.md](profiles.md) and [previewAll.md](previewAll.md) (wave 57). Nothing here was run on a device or on the owner's site.

> This note supersedes: in `studio.md`, "the tab assignment is one table in the test" (the tabs and groups are now the app's, see below) and "Signal ... placeholders", "portrait only", "no side dock" for the Studio drawing; in `profiles.md` and the Studio README, "the Studio page has no editor for phone profiles"; in `previewAll.md` "Not matched", the three items: the dock magnification sample bulge, the hub's Widgets section, and Glance off the Glance page drawing the current backdrop.

## Studio = app (CFG-70)
- **The tab and section of every Studio field come from the app.** Each schema field names the app Settings row that edits it (`row`, "topic/English title", the key `SettingsTabLayout` uses). The generator (`core-data StudioSchemaW56Test`) reads `app/.../ui/SettingsTabLayout.kt` as text (the app module is not a dependency of core-data, the same way it already reads the dock source), resolves the row to its tab and section, and writes `tab`, `group` (the section header) and `row`; `tabs[].sections` lists the app's section headers in order and the fields are written in the app's order. The only editorial part is which row a field belongs to; a field without a row of its own (the clock's dragged place, a clock tile's options, the page the Home button returns to, the Lab override) names the row the app keeps it next to.
- **Guarded from the app side.** `StudioTabsW58Test` (app, Robolectric) checks over the real built Settings: (1) for each field, `SettingsTabLayout.whereIs(row)` is the Studio tab and section; the section lists and labels match; (2) every named row is built in one of three home configurations; (3) the settings model: every switch, choice, stepper and slider of the built Settings is invoked with a recording `updatePrefs` (rows of topics that write other stores are not invoked, so nothing leaks into later tests), and every export key a row changes must be shown by Studio in a section whose rows change it (a row may change a second key on the way: choosing a Radar layout also unpins it). So a row moved in the app, or a field mapped to the wrong row, fails a test, and regenerating with `STUDIO_REGEN=1` moves the field.
- **Same names, same order, on the page.** The panel renders `tabs[].sections` in order. A section with nothing a file can carry (External displays, App groups and sessions, Hidden apps, Open with, Privacy, the panel's Sections, Groups and rules, Clean up, Access and privacy, Help and recovery, About) shows its header and one line saying it is set on the phone. Looks shows the quick looks inline. A row of four or more fields (the Glance and Pages wallpapers) gets the app row's title as a small heading.
- Tab ids (`home`, `look`, ...) are kept from wave 56 so a saved "last tab" still opens; labels are the app's English keys in capitals.

## Studio Profiles panel (CFG-71)
- **Where**: APPS > Profiles, the app's place. The phone profiles live in the Backup the Studio profile holds (`extras.base`), so Export writes them as the Backup's `workspaces` and `dock` sections and the app's import takes them as they are. With no Backup the panel offers "Start a profile list" (the phone's main profile Home, id `default`), and says that importing such a file replaces the phone's list (the phone's Home keeps the home that is on it, because its arrangement is not in the file).
- **Same model as the phone** (`core.js`, pure, node tested): New from the starts generated into the schema from `ProfileStart`/`ProfileStarters` (`profileStarts`: carries and starter values as the Backup's JSON texts): Current setup copies the active profile with the live values of what it carries; Empty, Work, Calm and Desk are one page (in the shape `ProfileStarters.arrangement` writes), an empty dock, the start's values over the global ones for the groups ticked (an unticked group's starter value is dropped), Work puts the suggested work apps on page 1 and in the calm centre, Calm lets the messaging and alert apps through. Rename (unique names), Duplicate, Delete (not the active one, not the last). Switch follows `ProfileSwitch.plan`: the profile left keeps its carried keys as they are now, the global values come back, the new one's values go over them, its global values are kept aside in `dock.globalSettings`. Ticking a group follows the phone's rules (on the active profile the live values become its own and are kept aside; unticking puts the global value back; on another profile the group starts from the global values). On Export the active profile takes the live values of what it carries (the phone writes them through as they change).
- **Suggestions**: a Backup carries no installed-app list, labels or categories, so Studio suggests from the apps the file names (pages, hidden apps, profile homes and pins, app groups) with the suggester's own package tables (generated into the schema as `appSuggest`; a core-data test classifies every entry with `AppGroupSuggester.classify`), the work profile (`#user` other than 0) and the bank / pay words; the phone also reads declared categories and utility words, so it may suggest more. Each suggestion is an editable list (2 to 4 ticked, the App groups store's rule) saved as an App group in `dock.groups`, optionally linked to a profile (`groupLinks`). With fewer than two apps of a kind, the panel says suggestions run on the phone.
- **Checked by the app**: `tests/make-fixtures.js` writes `fixtures/studio-profiles-backup.json` with Studio's own functions; `feature-dock StudioProfilesW58Test` imports it with `StateCodec`, `WorkspaceFileSource` and `WorkspaceJson` and checks the profiles, carries, starter values, notification apps, page 1, the app group and its link, the active profile and the kept-aside global value.

## Studio preview (CFG-72)
- **Signal wallpaper**: approximations of the app's painters (`LivingWallpapers.kt`: Beam a tapered beam from the bottom edge with a white core and beads, Spire a cusp from the lower third with a bloom and a white core, Halo a tilted ring, Laser thin lines, Shaft a wide band; the effects as before) in the theme's accent over its black gradient (pale in Light, fainter, as the app's gain is lower on light), still frames. The canvas no longer says "placeholder"; the footer says they are approximate. System and Picture remain placeholders.
- **Landscape**: a switch under the preview draws the Glance and Pages at 740 by 360 dp: the dock at the side edge `dock.edge` chooses (Left or Right; Bottom stays a row), the landscape grid (`lCols`, `lRows`), the landscape scroll axis and the landscape clock place. Radar, the disc, Comms and Recents stay portrait.
- **Magnification**: with Magnify icons on, the dock row is drawn grown under a still sample pointer (a small ring) at the strength's peak (1.3, 1.6, 2.0) with a cosine falloff over two icons; the row shrinks a little to stay on the screen and the group chips move up.
- **Clock place**: the clock box is draggable on the Glance (pointer capture; the box is kept on the screen) and, focused, moves with the arrow keys (Shift for 5 percent); it writes `glanceClockX`/`Y`, or the landscape pair in landscape, to the hundredth (`clockFromBox`, node tested); the sliders follow.

## App preview gaps (CFG-73)
- **Dock bulge**: `DockRail` has an optional `demoPointer: Float?` (default null: the real dock is unchanged); with magnification on it rests a still pointer at that fraction of the row (`MagnifyField.demo`), so the row is drawn magnified with no finger, no tooltip, and taps still reach the pressed icon. `DockPreviewStage` passes 0.3 (over the second icon) when magnification is on. `DockDemoPointerW58Test`.
- **Widgets section**: `CommsPreview` shows, when the panel's Widgets section is on, two sample cards (the section's minimum card height and a taller one, dashed, "Sample widget 1/2") with the panel's section order, above the Comms column when Widgets is the first section, below otherwise. No widget is hosted in the Preview's sandbox. `CommsPreviewWidgetsW58Test`, `StudioPreviewW58AppTest`.
- **Glance wallpaper on a page**: when the home behind Settings is on a page whose wallpaper is not the Glance one, the Glance topic draws the Glance's own backdrop (`HomeSurfaceBackground` for the Glance, still: no animation, first frame, no alert) in the sandbox under the real Glance surface; with a shared wallpaper or the home on the Glance the capture is used as before. `PreviewGlanceBackdropW58UiTest` (pixel check: the Glance's red, not the page's blue).

## Studio address (CFG-74)
`LiftoffStudio.URL` is the one constant (documented "set when published"; `PLACEHOLDER_URL` is the reserved example.com address). `PUBLISHED` is derived from it; while it is the placeholder the row's value reads "Not published yet". A test checks no other source spells the address.
