# One Wallpaper picker: solid, gradient, signal, system live, picture (wave 34; HOM-16, PAL-24, NFR-14, NFR-18, CFG-03)

**Owner:** "Make sure wallpaper picker supports live wallpaper selection as well as selecting any image from the gallery. If the user selects an animated gif, they can select the first still ... or for the gif to be animated; if Animated, then can choose to animate it once or loop; loop can be continuous or bounce ... " Then: "I want to also be able to select a video, and Videos and animated GIFs have to give the alert when turned on that it may consume excessive battery and compute and may cause the phone to heat up or lag." Then: "Omit the bounce effect for video." Standing note: "the comic-book lines alert appears when there is an issue, like lack of connectivity, it's like a spider-sense."

## 1. One picker, five kinds
Ground Control > Home screen > Glance wallpaper / Pages wallpaper (the wave 26 rows) is the only wallpaper UI. Kinds (`WallpaperKind`): Solid colour, Gradient, **Signal wallpaper** (the existing two-slot `BackgroundChoice`, stored under the unchanged id `live`, so nothing migrates; only its label changed from "Live wallpaper"), **System live wallpaper** (`system`) and **Picture** (`picture`). The separate "Background" entry of the Home quick sheet is another stream's to remove; settings had already folded the Background pane into the wallpaper rows in wave 26.

## 2. Picture
- Source: the system Photo Picker (`PickVisualMedia.ImageAndVideo`, no permission); devices without it use `ACTION_GET_CONTENT` with `image/*` and `video/*`. Seam: `MediaPickerFactory` (`LocalMediaPicker`).
- Because a picker Uri is temporary the file is copied into `files/wallpapers/<surface>-<id>.<ext>` (`PictureFiles`, `AndroidPictureImporter`, IO dispatcher, never throws; failures are `ImportFailure` results shown as a quiet line). Stills are decoded to at most the screen x 1.5 and stored as JPEG (PNG when transparent); GIF and animated WebP keep their bytes up to 30 MB; a video keeps its bytes up to 200 MB; a larger file is refused with the limits named. The old copy is deleted when the picture is replaced or removed ("Remove picture"). Switching the kind away keeps the copy (the user may switch back); a missing file draws the wallpaper's solid colour and the pane says so.
- Fit: Fill (centre-crop, default) or Fit (black bars); dim 0 / 25 / 50 percent (a black layer, `PictureSpec.dim`).
- **Backup.** The file is local-only: `wallpapers` is in `StateSchema.BACKUP_EXCLUDED_FILES` and both backup xml files, and the prefs that name or describe it (`wpGlancePic`, `PicAnim`, `PicVid`, `PicMs`, `PicOk`, `PicBounce`, and the Pages ones; `StateSchema.WALLPAPER_PICTURE_KEYS`) are device-bound (never exported or imported). The fit, dim, mode and kind do travel. A restored install with kind Picture and no file shows the solid colour.

## 3. Animated GIF, animated WebP and video
Animation is detected from the bytes (`AnimationSniffer`: GIF frame count and per-frame delays read without decoding pixels; WebP VP8X animation flag; MP4/WebM by signature; video length from `MediaMetadataRetriever`). The choices: **Still (first frame)** or **Animated**; Animated: **Play once** or **Loop**; Loop: **Continuous** or **Bounce** (Bounce is GIF and WebP only; a video has Still, Play once and Loop). `GifMode {Still, Once, LoopContinuous, LoopBounce}` is the stored mode; a stored Bounce on a video reads as Continuous.
- Clock: `GifTimeline` (pure): Once ends on the last frame; Continuous wraps; Bounce plays 0..n-1 then n-2..1 (the end frames once per cycle). Real per-frame delays; a delay of 10 ms or less is 100 ms as browsers do.
- GIF render: all frames are decoded off the main thread through `android.graphics.Movie` (random access to any frame time, so rewinding is just an index) into a cache bounded at 48 MB at the screen size or smaller (`PictureLimits.cacheScale`: 1, 3/4 or 1/2 of the screen-bounded size). `FramePlayer` redraws only when the frame changes, sleeping for the frame's delay in between, using `infiniteFrameNanos` (the infinite-animation policy). A GIF that does not fit the cache streams through `AnimatedImageDrawable` for Once and Continuous; Bounce then loops instead and the picker says "Too large to bounce, looping instead".
- Animated WebP: `AnimatedImageDrawable` (cannot seek), so Bounce loops instead: "Bounce needs a GIF, looping instead". `ImageDecoder`/`AnimatedImageDrawable` cannot rewind, and `Movie` reads GIF only; that is why.
- **Video:** `MediaPlayer` on its own handler thread (preparing and decoding never on the main thread), into a `TextureView` over the still poster frame; always muted (`setVolume(0,0)`), no audio focus, no wake lock; Once stops on the last frame, Loop uses `isLooping`. **No Bounce** (owner): no seeking backwards, no frame cache for video. Media3 is not a dependency, so `MediaPlayer` is used.
- Policy: motion off (system animation scales, or battery saver `PowerManager.isPowerSaveMode`) shows the first frame with the visible note "Animation is off ...". Playback exists only while the app is resumed and its window focused (`rememberRadarActive`): the player is released and the loop is parked when not. Radar shows an animated picture as its still frame and never creates a player (`HomeSurfaceBackground(play = false)`). No work on the main thread but drawing.

## 4. The power warning
Turning on any animated mode of a GIF, WebP or video, or switching to a picture that plays and was never confirmed, first shows "Animated wallpapers use more power" with "This may consume excessive battery and compute, and may cause the phone to heat up or lag." and the buttons "Use anyway" and "Choose a still instead" (GIF/WebP) or "Cancel" (video); dismissing is the second button. "Use anyway" sets `PictureSpec.powerOk` for that file, so it is asked once per chosen file, not on every launch or mode change; a new file starts as a still and unconfirmed. While an animated picture plays the pane shows a standing line under the choices, and the settings row summary reads "Picture: Animated, uses more power" (or "Video"). Buttons are 48 dp, the line is a live region, the dialog is a Compose `Dialog`.

## 5. System live wallpaper
An app cannot draw another app's live wallpaper. The kind draws nothing but its dim: the window is `windowShowWallpaper` with a transparent background (themes.xml), `SystemWallpaperLayer` is a transparent box (dim 0 / 25 / 50 percent), and `GlanceSurface`, which painted an opaque black base under its underlay, now has no base colour when the Glance wallpaper is System. The pane shows the active live wallpaper's name (`WallpaperManager.getWallpaperInfo()`, when the system gives it) and a button that opens `ACTION_LIVE_WALLPAPER_CHOOSER`, then `ACTION_SET_WALLPAPER`, then display settings. There is no legibility scrim (the colours are unknown); the dim chips are the control.

## 6. The spider-sense alert
Before: the comic speed lines were drawn only by `SignalBackground`, only when the signal wallpaper had an item, and Radar True black composed nothing. Now `SpiderSenseAlert` (the lines alone, same `ComicPainter`, same motion clock and reduced-motion still frame, signal collected only while composed and started) is drawn by `HomeSurfaceBackground` over every kind that does not already draw the lines (solid, gradient, picture, system, signal with no items); `RadarBackgroundLayer` draws it above the dim for Dimmed and as its only content for True black. No new alert condition: it is still "no connectivity".

## Not done / limits
Playing a real GIF, WebP or video, the Photo Picker, `WallpaperManager` and the look of the system wallpaper through the window are device-only. Robolectric has no `ImageDecoder` and no video decoder, so stills are imported through a test decoder and video through a fake engine.
