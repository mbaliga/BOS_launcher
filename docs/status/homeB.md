# Home behaviour: status (wave 2, stream "homeB")

Status vocabulary: built = compiles and covered by JVM unit tests; partial = some of it is built or wired; not started; unmet. Nothing here is device-confirmed (no device or notification-listener session was available).

| ID | Status | Note |

| HOM-09 | built | Settings toggles "Notification badges" and "Count in badges" (stored in `LauncherPrefs`, read live by `BadgedAppIcon`). `HubNotification` now carries the profile id (from the notification's user) so work-profile apps are badged by their own profile's notifications and the preview in the app menu is per profile (`Badges.previewFor`). Tests `HOM_09_*`; dot rendering in `HomeEditScreenshotTest`. Badges need notification access to be granted by the user; not checked on a device |

Not done: archived state is not read (the system keeps listing the app, no public flag used); the 1 s figure is by construction, not measured; folders, dock and widgets are not in the live layout yet, so `PackageReconcile.applyToState` is not on the live path |

## Review pass (adversarial)

Defects fixed: (1) a layout loaded from another size class could carry "removed from home" keys for apps uninstalled since, because the prune only ran when the app list changed; the size-class binding now prunes after switching class. (2) The Usage tab did not re-check usage access after returning from the system settings screen; it now re-checks on resume.

Final statuses are as in the table above; none upgraded. Remaining partials need a device or work owned by other streams (hosted widgets for HOM-13/14, tile rendering for HOM-12 remove handles, folder and dock layout for HOM-10/11, widget placement of the Files/Usage/Timeline panels for HOM-15/17/18). Known unaddressed: size-class store reads SharedPreferences on first composition (same pattern as the other stores); a class switch during edit mode lands on the undo stack as one change.
