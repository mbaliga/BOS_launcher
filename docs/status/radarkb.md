# Stream status: Radar keyboard, scope wheel, Orbit feel, Ground Control keys

Nothing here is device-confirmed. "built" means it compiles and the pure logic has JVM unit tests; the Compose glue is compiled but not exercised on a device or by a screenshot test.

| ID | Status | Note |
| --- | --- | --- |
| PAL-07 | built | `RadarKeyboard` (pure, tested): Up/Down select, Enter runs, Tab/Right/Menu/Shift+F10 open the action list (core-input `ContextMenus`), Esc closes, Tab and Shift+Tab always consumed so focus stays in the palette. Wired into `SearchScreen` via `onPreviewKeyEvent`. Left with a selection moves the wheel (Right opens the list). Selection scrolls into view in Flat and Filmstrip; Orbit selects only tiles that have a slot. Not driven on a device |
| PAL-18 | built | `RadarLayoutPolicy.effective` (tested): keyboard or pointer in use means Flat unless `LauncherPrefs.searchLayoutPinned` (new, last field, persisted). Picking a layout in Ground Control pins it; a "Keep this layout with a keyboard" toggle unpins. `LocalInputMode` (default Touch) is provided for the host; Radar also tracks key and pointer events itself (soft-keyboard key events do not count). The host does not yet provide the real tracker value, so Radar opened by a shortcut starts in Touch until the first key or mouse event |
| PAL-19 | built | `ScopePrefixes` (parse, prefixFor, applyWheel, effectiveScope, editable `Mapping`) and `ScopeWheel` in feature-grid. Prefix text and wheel update each other; Left/Right move the wheel (caret keeps Left/Right while typing until it is at an end). Defaults a, c, f, s (actions and settings), w (web). The prefix editor UI and the empty-state prefix list (PAL-13) belong to the palette stream; the mapping is editable in code but not yet persisted or shown in Ground Control |
| PAL-20 | built | One text size state (`rememberRadarScale`) for the whole Radar screen: pinch and Ctrl+scroll in all layouts, remembered. Long-press and right-click (`secondaryClick`) open the same preview in Flat, Orbit and Filmstrip, for every result type (people show their channel buttons in it). Orbit and Filmstrip captions scale with it. Behaviour change: long-press on an app or person in Orbit/Filmstrip now opens the preview (its OPTIONS button leads to the old app sheet) |
| PAL-23 | built | `OrbitFeel` (SharedPreferences, defaults equal the old constants, tested against the old formulas) read live by the Orbit; `OrbitFeel.labHooks` listed on the Lab page as tap-to-step rows plus a reset row (`app/ui/Lab.kt`, additive). Final values still have to be tuned on a device and committed as defaults |
| CFG-13 | built | `GroundControlNav` (pure, tested) plus handler in `SettingsSpace`: Left/Right category, Up/Down rows, Enter flips a toggle, runs an action, opens a page or starts adjusting (arrows then adjust, Enter/Esc ends), Esc backs out (edit, page, search, then close). D-pad, A and B map to the same keys. Cursor ring shows only after a hardware key. Same model in both orientations (no orientation logic). Touch and pointer use the existing rows and swipe |
| CFG-05 | partial | Keyboard operation of Ground Control is built (see CFG-13). Every row is a `SettingsIndex` entry (built from the live category list) and `SettingsResultSource` / `CategorySettingsSource` expose them; `SearchScreen` shows matches as Settings results under Actions (needs 2+ characters and the Actions search switch) and opens Ground Control on the result's category. It does not yet scroll to or highlight the exact row. Note for the palette stream: the interface lives in feature-grid, not search-engine |
| CFG-14 | built | Ground Control search uses `SettingsIndex.search` (name, description, category, exact value; every word must match; ranked) instead of the old substring filter. Same index that Radar queries |
