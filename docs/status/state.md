## Other

- Build-31 bridge: `StateService.bridgeBuild31` runs once at start (before any store is read), writes the old preference files out as a state document snapshot, then sets a schema marker. One way; old files are never modified. Round-trip tested from fixtures that reproduce build-31 SharedPreferences XML files (`core-data/src/test/resources/build31`).
- Settings are encoded by the existing `LauncherPrefsStore` logic over an in-memory preferences map, so every `LauncherPrefs` field is covered; a reflection test fails if a new field is not carried.
- Device-bound values (widget ids, private background picture path, onboarding flag) are never exported and are kept from the live device on import.
- Shared-file edits (all small): `LauncherStores.kt` (+`HomeLayoutStore.replace`), `AndroidManifest.xml` (2 attributes), `SettingsCategories.kt` (2 lines), `HomeScreen.kt` (2 snapshot calls). `MainActivity.kt` and `Onboarding.kt` are owned by this stream.
