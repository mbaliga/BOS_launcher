# Wave 13 audit: Launchpad stream (STR-01..05, 07..11, 13, CFG-04)

Method: read the spec row, the decision docs (cardTune, launchpadCard, notifFix, groups, launchpadGroups) and the code path from the running app (HomeScreen, LaunchpadPanel, LaunchpadContent) to the behaviour, then the tests. Nothing here is device verified; Robolectric and JVM tests only.

| ID | Status | Note |
|---|---|---|
| STR-01 | built (fixed) | Verified: edge drag, sliver return zone (48 dp minimum), handle, shortcut, Back, reduced-motion snap are wired in `HomeScreen`; hit-testing under the scale uses the graphicsLayer transform, and the overlay widens the sliver to the 48 dp zone. FIXED: the reveal gesture block restarted by a rotation or size change (its `slideDp` key) left `dragging = true` for good, so `LaunchedEffect(open)` never animated again and the card could stay half open. The block now settles through `abandonDrag()` in a `finally`; `endDrag` also reads the last requested fraction instead of the animatable's value, which could lag the queued snap. Test `STR_01_aDragCutShortByARotationSettlesInsteadOfSticking`. Process recreate: `leftOpen` is plain `remember`, so it comes back closed with the card at rest (not stuck). Found and left: the inner `leftSwipe` modifier on the same root box can never fire while the edge drag is enabled (the edge drag consumes first and `positionChange()` of a consumed change is zero); it is redundant, not harmful, and sits in shared `HomeScreen.kt` so it is not removed here. With reduced motion a live drag snaps the card to its end pose on the first pixel (cross-fade semantics), then settles on release: owner decision whether a live drag should still track. Frame rate and feel: device only. |
| STR-02 | built (fixed) | Verified the roomy single list, "+N more", strip, auto-cancel only after `HandOff.Sent`, close only after a hand-off, and that every PendingIntent we do not own goes through `PendingIntentLauncher` (content intent, action chips, reply, media session activity); the other `PendingIntent.getActivity/getBroadcast` sites (widget, alarms, desktop, group switcher, foreground notification) are ours, immutable, explicit, and fired by the system. Existing tests cover opt-in on 34 and 35, none on 33, cancel and security exceptions, fallback. FIXED: a failed inline reply said "Couldn't open <app>"; it now says "Couldn't send your reply" (new string in `L10nW13auditLaunchpad.kt`, 8 languages). Not changed: a tap marks the notification read even when the hand-off fails (spec says mark-read stays). Android 14 background-start behaviour is device only (checklist item). |
| STR-03 | built (fixed) | There was no test that performed the touch slides themselves (only keys and buttons). Added `STR_03_slidingARowLeftRunsThePrimaryAction` and `STR_03_slidingARowRightOpensThePaletteAndItStaysUntilChosenOrTapped`. FIXED: in a right-to-left layout the palette cells were laid out from the right edge while the row slides physically right, so the palette sat under the row; they are now laid out from the physical left, and the "primary" label sits on the physical right (`STR_03_inARightToLeftLayoutTheRightSlideStillUncoversThePaletteOnTheLeft`). FIXED: with no primary action (left action None) the row still slid left over a blank background; it now does not move that way. Gesture conflicts: the row's `detectHorizontalDragGestures` consumes before the panel's own close-on-left-swipe, and the edge-open drag is off while the panel is open, so no conflict with the home underneath. |

FIXED: with groups configured the grouped list is computed off the main thread, so the first frames had an empty list and its arrival counted every waiting item as new, widening the indicator on each cold start. `rememberWaitingHeadline` takes `ready`, and the indicator passes "plain or grouped is available" (`STR_09_aListThatAppearsOnlyWhenNotReadyIsNotNewItems`). | STR-13 | built (fixed) | Verified assignment precedence (conversation, person, app, then rules; first match wins), a rule or assignment pointing at a deleted group is ignored, a person linked to a removed contact is still found by name, single names and empty last names never match or crash, and the 500-notification budget test. FIXED: Turkish dotless i (`ISIK` and `ısık` were different keys, so "SINAN IŞIK" did not match "Sinan Işık"): `PersonNames.fold` maps U+0131 to i (`STR_13_turkishDottedAndDotlessIAreOneLetterWhenMatchingNames`). Other non-decomposing Latin letters (ł, ø, đ, ß) are deliberately not folded: that would change the stored person keys of existing assignments (owner decision, would need a migration). FIXED: a very long unbalanced name ran the bracket regex quadratically; names are cut at 512 characters before matching (`STR_13_aHugeUnbalancedSenderNameIsHandledInBoundedTime`). FIXED: a negated condition with a blank value ("app is not ...") matched every notification; blank or decoration-only values are now unevaluable and never match (`STR_13_aBlankConditionValueNeverMatchesEvenWhenNegated`). Not done, as before: group icon choice, drag reorder. Contacts reader is device only. |

## Dead code found

- Removed: `GroupView.isFallback` (no caller, no test).
- Left because only tests call them (removing would mean editing tests): `LaunchpadCardGeometry.contentWidthPx`, `visibleCardBounds`, `settleMs`, `CardEdge.forEdit`, `RevealLayout.forWindow`, `LaunchpadShortcuts.opensLaunchpad`, `GroupResolver.conditionMatches`, `previewWinning`, `GroupSummaries`, `GroupWaiting`-style helpers `priorityWaiting` and `priorityAccent`. `GroupSummaries` is the English summary; the UI builds its own localized text in `GroupTexts`.
- Redundant: the `leftSwipe` modifier in `HomeScreen` (see STR-01).
