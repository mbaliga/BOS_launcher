# Wave 22: independent audit of the Radar glass, mic, X, Orbit typing and the web rows

Scope: PAL-06, PAL-07, PAL-12, PAL-18, PAL-20, INP-12, INP-13, NFR-13, NFR-14, NFR-15. Read in the code and the tests, not in the notes. Nothing here was run on a device; no TalkBack, no real IME, no real recogniser.

## Defects found and fixed (each with a test)

1. **The Clear X, Close and the mic could not be reached from a hardware keyboard or d-pad.** Radar's key handler swallowed Tab, Shift+Tab and the arrows (Tab with nothing to open, "focus stays in the palette"), so the buttons that wave 21 documented as "operable from a keyboard" were only reachable by touch or TalkBack. Now Shift+Tab, or Up with no row selected, moves focus to Clear (with text) or Close (empty); Tab with no results moves it to Clear or Close (and Tab again on to the mic), Down with no results to walk and a mic present moves it straight to the mic; while a button has focus Tab, Shift+Tab, arrows, Enter and Space belong to the focus system and the button (Escape still closes); focus returns to the field on Clear, and a stale "button has focus" flag heals itself the moment the field regains focus. Tests `INP_13_shiftTabFromTheFieldReachesClearAndTabReachesTheMic`, `PAL_18_enterOnTheFocusedClearEmptiesTheFieldAndFocusReturnsToIt`, `PAL_07_upFromTheFieldReachesCloseWhenNothingIsSelectedAndEnterCloses`, `INP_13_downFromTheFieldWithNothingToWalkReachesTheMic` (`RadarAuditGlassW22UiTest`).
2. **TalkBack read the mic before most of the Orbit rings.** The ring tiles carry traversal indices 0, 1, 2 ...; the field and the mic have none (0), so with no reading group the mic sorted ahead of tile 1 onward (and the typed strip pills, also 0, ahead of the rings). The results area is now one traversal group and the Orbit's rings a group inside it. Test `NFR_13_theTypedOrbitStripPillsAre48dpButtonsAndTheRingsAndTheResultsAreReadingGroupsSoTheMicIsReadLast` (property checks on the semantics tree; the real reading order is TalkBack-only).
3. **The typed strip pills were 34 dp high with no button role and clipped at a big text size** (strip fixed at 52 dp, 6 dp padding). Each pill (and Filenames) is now a 48 dp high labelled button around the same visual pill; the strip grows with the text size instead of clipping. Same test.
4. **Clear did not bring the keyboard back** if it had been hidden (it only re-focused the field). It now calls the same show-keyboard path as a tap on the SEARCH label, keeps focus in the field and Close takes its place (`PAL_18_aTapOnClearKeepsTheFieldFocusedAndEmpties`; the keyboard rising itself is device-only).
5. **Not fixed, measured, owner decision: the glass shade is measured where the glass is with no status bar and a closed keyboard.** The top zone is 8 to 60 dp (the field really sits under the status bar and cutout) and the mic zone is the very bottom edge (the mic rides above the keyboard, where Radar spends its life). Measured on the default pair, portrait, normal intensity: a top zone of 8 to 84 dp needs a shade of 0.77 (0.83 for 8 to 120) against the 0.37 applied; a mic zone reaching 140 dp above the bottom needs 0.46 and one reaching 300 dp needs 0.64, against 0.40. Applying them makes the default glass much darker (the test `NFR_15_glassTextHasAaOverEveryBackgroundPairAtLevels0And4` also demands at most 0.5 for the default pair), which is the opposite of what the owner asked for in wave 21, so nothing was changed; the zones' comment in `Glass.kt` records the numbers. The honest reading: white text on the glass over the default pair is AA only in the positions that were measured, not in the positions the field and the mic usually take.
6. **Push-to-talk edge cases.** A late callback of an older press (a recogniser still finishing) could end the new listening; a late result after the control left the screen still wrote into the field; a blank final result (silence) replaced the typed text with nothing; a key held while focus moved away never released. Each press is now a session, a disposed control ignores everything, blank text is dropped, and losing focus releases. A refused microphone permission (including a permanent one, which returns at once with no dialog) used to be silent: it now says "Microphone is off. Allow it in Settings to speak to search." (eight languages, `L10nW22auditGlass.kt`). Tests `INP_13_aLateCallbackOfAnOlderPressCannotEndTheNewListening`, `..._theFinalResultOfTheReleasedPressStillArrives`, `..._nothingReachesTheFieldAfterTheControlLeavesTheScreen`, `..._silenceNeverClearsWhatIsInTheField`, `..._aPressThatFindsNoPermissionAsksOnceAndTheNextPressAfterAGrantListens`, `..._theRefusedMicrophoneMessageIsTranslatedInAllEightLanguages` (`VoiceAuditW22Test`).
7. **The contact channel buttons (Call, Message, Email, WhatsApp, Telegram, Signal) had English-only TalkBack names.** Now `L10n.tr`.
8. **Dead code removed.** `SearchResults` (public, no caller) with its private rows (`Row`, `AppRow`, `PersonRow`, `SimpleRow`, `WebRowView`, `SuggestionChip`); the typed-query branch of `QueryDisplay` and `BlinkingCaret` (the old bottom field layout; the label is all that is drawn); `glassBorder` (unused); `VoiceInputManager` reduced to its one `release()` that the home still calls (the recogniser wrapper had no caller; `HomeScreen.kt` is a shared file and was not touched). `PaletteSession` named in older rows no longer exists in the code.

Also added: `PAL_18_aQueryOfOnlySpacesKeepsClearAndNoCloseAndEnterDoesNothing`, `PAL_06_pastingTenThousandCharactersIsHandledAndTheFieldStaysUsable`, `PAL_18_everyRingTierNameOfARestingAndOfATypedOrbitIsTranslatedInAllEightLanguages`.

## Second audit (adversarial review) additions

9. **Keyboard focus was invisible** on Clear, Close and the mic (no indication on the glass buttons), so the new keyboard reach could not be seen. A 2 dp white ring now shows on focus (`GlassButton`, mic).
10. **A stale "button has focus" flag** when Close and Clear swap places while one has keyboard focus (text arriving by voice or paste): every key was then passed on to a node that no longer exists. The flag is dropped and the field takes focus back. Test `PAL_18_closeLeavingWhileItHasFocusHandsTheKeysBackToRadar`.
11. **Contact channel buttons were 32 dp**: now a 48 dp target around the same 32 dp look (NFR-13 gap closed for them).
12. **Dead code**: `SuggestionGroups` (no caller) removed.
13. The first note said Tab with no results reaches the mic; the code (and test) send it to Clear or Close first, then the mic. Corrected in item 1.

Verified by reading in this audit, no change needed: PushToTalk sessions (a late final after release still arrives, an older press cannot end a newer one), finger slide-off and a second pointer (`waitForUpOrCancellation`), Clear keeps focus and re-shows the keyboard, Close and Clear exclusive (Close iff the raw query is empty; spaces-only shows Clear), Enter with no result and a blank query do nothing.

## Residue (device or owner)

- Landscape: the mic strip clips the faint lower wheel labels at the strip boundary (cosmetic, open point (a)); a fade would need an offscreen layer over the animated rings, not done.
- Glass shade about 0.4 over the default pair (open point (b)): owner decision.
- TalkBack order, real IME and gesture-bar insets, cutout, 320x480 split-screen, frame time (NFR-05), a hardware keyboard, the recogniser (busy, missing, offline, long silence), rotation while held and process death: device only.
- `HomeScreen.kt` still imports `VoiceInputManager` for its no-op `release()`; remove both in a later wave that owns that file.
