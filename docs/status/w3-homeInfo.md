# Home behaviour, wave 3 (stream "homeInfo"): status

Status vocabulary: built = compiles, covered by JVM or Robolectric tests and has a live path in the app; partial = built and wired, but the last step needs a device, hardware, a second display or an owner decision (named per row). Nothing here is device-confirmed.

| ID | Status | Note |
| --- | --- | --- |
| HOM-06 | partial | Closed here: `WorkProfileState` (profile availability broadcasts, quiet-mode query and `requestQuietModeEnabled` all on an IO scope) feeds one shared state. Home shows a "Pause work apps" / "Resume work apps" chip while a work profile exists (`WorkPauseChip`, hidden in edit mode), the drawer chip reads the same state (it used to query `UserManager` on the main thread and kept a stale local copy), and home icons of a paused profile are dimmed with a pause mark and are not launchable (`AppPresentation`). Work badge: still the system badge from `getBadgedIcon`, no second badge is drawn on top of it. Tests: `HomeInfoW3Test` (`HOM_06_*`), `HomeEditModeTest` (chip), `HomeInfoW3AuditTest` (off the main thread). Needs a device: that the system badge is present on the user's launcher icons, that the chip pauses and resumes a real work profile (needs the default home role), that private space (API 35+) appears only while unlocked, and the pre-API-35 rule that any secondary profile is work. |
| HOM-10 | partial | Closed here: archived state. `AppFlags.archived` reads only the public `ApplicationInfo.FLAG_INSTALLED` of each launcher entry (clear = archived, no hidden flag), `AppEntry.archived` / `AppRecord.archived` carry it through `LiveReconcile`, an archive or restore is a `changed` entry in the diff (icon evicted, key keeps its place on the page), and the icon is drawn dimmed with a down-arrow mark but stays launchable because launching restores it (`AppPresentation`, `AppMarkGlyph`). Tests `HOM_10_*`. Needs a device: that Android 15 builds really keep archived apps in `LauncherApps.getActivityList` with `FLAG_INSTALLED` clear (the one assumption the archived mark rests on), and the 1 second figure measured with a real install, update, uninstall, disable, archive and suspend (it is bounded by construction: conflated flow plus the 250 ms coalescer). Folders and the dock are not on the `PackageReconcile.applyToState` path: the live page resolver already drops missing keys without gaps, so no extra step is needed for pages. |
| HOM-11 | partial | Closed here: (1) pinch, "Denser grid" and "Sparser grid" now move the density setting when "Grid follows window size" is on (`AdaptivePrefs.stepDensity`, steps until the derived grid really changes, bounded 0.5 to 2) instead of editing the fixed grids; (2) folders and widgets are part of the per-size-class arrangement: their positions live in each class's stored page list, a folder made in one class is placed in the others, a dissolved one leaves no gap, an app filed into a folder in one class no longer reappears from another class's stale page list (fix in `HomeResolve.layoutFor`), and a widget wider than a narrow class's grid is split onto its own page, not lost. Tests `HOM_11_*`. By design the definitions (folder members, widget spans) are shared by all classes. Needs a device: a real fold or unfold, split-screen resize and display move, to see positions kept. |
| HOM-12 | built | Edit mode on the live grid: in "Edit home" an app or shortcut tile is grabbed at once (no long press) and dragged to a new slot or page with the existing edge-dwell and drop-onto rules, every tile, widgets included (handle added in review, no Robolectric test for the widget handle), carries a remove handle (`EditHandleBox`, minus badge, content description "Remove from home: name") that removes it from home (apps through `removeFromHome`, folders, links, shortcuts and widgets through `HomeItems`), the undo stack records both (20 changes, wave 2), outside edit mode the same quick drag changes nothing. Tests `HomeEditModeTest` (Robolectric): handle on every app and tap removes it without opening a menu, no handles outside edit mode, immediate drag rearranges and loses nothing, same drag outside edit mode does nothing; `HomeBehaviourTest` for undo depth. The scrolling styles (List, XMB, DSi, continuous) have no page arrangement to edit, so the banner and undo apply to the pages only. |
| HOM-15 | partial | Closed here: the Files panel is now a tile on home (Home items sheet, "Files panel"; a link item whose target is `liftoff-panel://files`, tapping opens the panel at that tab), long-press a pinned folder to show only its files, "Remove" in Settings, Home, Home panels gives the grant back (`releasePersistableUriPermission`) so the folder and its files leave the panel, files per folder setting (10, 20, 50). Tests `HOM_15_*`, audit `HOM_15_filesPanelReadsOnlyGrantedTreesAndNoBroadStoragePermission`. Needs a device: the system folder picker and opening real files and folders with the user's file manager; the panel shows file names, not live thumbnails inside the tile. |
| HOM-17 | partial | Closed here: the Usage panel is a home tile, with a period setting (Today or Last 7 days, in the panel and in Settings), and tapping an app row launches it. Tests `HOM_17_*`. Needs a device: usage access granted in system settings, and real numbers compared with the system's digital wellbeing screen. The tile opens the panel; it does not draw the split bar inside the tile itself. |
| HOM-18 | partial | Closed here: the Timeline panel is a home tile in a tall sheet, depth setting (last 30, 100 or all 400 recorded opens), a switch for scheduled launches, day groups through `TimelineView.rows` (tested), and tapping an open launches the app. Tests `HOM_18_*`. Not done on purpose: the launch history keeps 400 opens, so "chronological view of app opens" is bounded by that store, which is owned by the launch layer. Needs a device only to see it with a real history. |
| EXT-10 | partial | Closed here: audit test `EXT_10_noAccessibilityServiceNoInputInjectionAndNoSystemPointer` (no accessibility service, no event injection, no system pointer in the desktop module or manifests) and `EXT_10_clicksAreHandedToTheLaunchersOwnWindowOnly`; the cursor click path (`SyntheticTouch`, dock and any control) and the phone panel were done in wave 2 and keep their tests. Needs a second display: the panel driving a focused desktop surface on a real external display with a real touch pipeline (move, tap, long press, two-finger scroll, keys, text), and the ongoing notification and the palette entry on a real device. |
| EXT-11 | partial | Closed here: "T2 rules apply to the mirrored surface": `CapabilityEvaluator.mirrored` (the same three facts the desktop module uses: not the default display, cannot host tasks, same pixel size) lifts the capability tier to T2 while a mirror is connected, so the persistent dock default, hover and shortcut hints apply to the phone surface that is being mirrored; a different-sized presentation display is not taken for a mirror; a task-hosting display stays T3. Tests `MirroredTierTest`, and from wave 1 `EXT_11_mirroredDisplayIsNeverEligible` (no offer, no second surface). Needs a device and a mirroring source: Android has no public mirroring signal, so detection stays an inference; a real Miracast or cable mirror is the only way to confirm it fires (and does not fire for a real extended display). |

Review fixes: a work pause request no longer re-reads quiet mode straight away (it could flip the chip back before the system applied it; the availability broadcast confirms), and widgets now get the edit-mode remove handle.
