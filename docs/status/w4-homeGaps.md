# Home surface code gaps, wave 4 (stream "homeGaps"): status

Status vocabulary as in earlier waves: built = compiles and is covered by JVM or Robolectric tests; partial = some of it is built or wired and a device or owner step remains. Nothing here is device-confirmed.

New code: `core-data` `TimelineLog.kt`; `core-catalog` `DropRule.kt`, `ProfileBadge.kt`, `GroupTiles.kt`, `UsageTileBar.kt`, `HomeIntentRouting.kt` (and additions to `WorkProfileState`, `HomeExtrasStore`); `core-input` toggle/choice/sheet entry kinds in `Input.kt`; `feature-dock` `HomeDockKeys`, `DockWidgetSlot`, `HomeBottomStack`, `WorkspaceManager.pinSink`; `feature-desktop` `DesktopWidgets.kt`; `feature-grid` shared widget host, profile badge glyph, usage tile bar, `bottomStackDp`; `app` `DockPinBinding`, `DesktopWidgetProvider`, quick sheet drawn from `ContextMenus.forHomeSheet`. Tests: `DockSingleSourceTest`, `DropRuleTest`, `ProfileBadgeTest`, `GroupTilesTest`, `UsageTileBarTest`, `HomeIntentRoutingTest`, `TimelineLogTest`, `HomeSheetMenuTest`, `DesktopWidgetsTest`, `BottomStackTest`, `HomeGapsW4AuditTest`.

Two older assertions were changed on purpose because the requirement changed: `HomeLayoutW3DockTest` used to assert that `widget:` keys cannot be pinned (they can now), and `HomeInfoW3Test` asserted that the timeline's deepest depth is 400 opens (it is 5000 now). No test was deleted or loosened otherwise.

The rail now reads `HomeState.dock` as its single source: `HomeDockKeys` writes every pin as `pin:<kind>:<id>`, `WorkspaceManager.pinSink` sends every `setPins` (rail, panel, item menu, group delete) to that list and the workspace's own list only mirrors it (`DockPinBinding`, started from the home and from the desktop's dock). Tests `HOM_02_*` in `DockSingleSourceTest`. Needs a device: that a real `AppWidgetHostView` in the rail updates and takes touches without stealing the rail's drag. |
