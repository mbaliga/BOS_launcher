| CFG-04 | built (device unverified) | The Launchpad rule removal (`removeRule`) and policy clear were already hooked through `DestructiveEdits` (`LaunchpadDestructiveEditTest`); `StateGapsAuditTest` keeps the hook list. New: the limiter no longer has a per-burst cap in the app. It decides per kind (`DestructiveLimiter.decide`: a second edit of the same kind inside 5 s takes none, a new kind always does) and marks the first snapshot of each burst; `SnapshotStore.take(pin = true)` pins that file (`pinned` marker in the snapshot directory), and pruning keeps the pinned file plus the newest 4. So a burst of any number of distinct kinds (eight in the test) keeps the state before its first edit and the state before the latest distinct kind, and a new burst releases the old pin. A pin on an edit that is identical to the newest snapshot moves onto that file. Tests: `DestructiveLimiterTest` (burst of eight kinds, new burst re-pins, identical-state pin), `StateGapsAuditTest.CFG_04_...`. The destructive snapshot is built on the calling thread (state read) and written on the state-io thread, as before. Not device-tested |
| NFR-18 | built (device unverified) | Widget ids no longer travel in the home arrangement, the export or the backed-up files. `WidgetIdSplit`: every `widget:<id>` in a stored arrangement value becomes the marker `widget:-<id+1>` (also inside stack targets, folders, dock and span lines); the real value goes to `device_bound` (excluded from cloud backup, device transfer and full backup). Applied to all four stores that persist home item keys: `home_layout` (`HomeLayoutStore`), `home_state` (`HomeStateStore`), `home_extras` (`HomeExtrasStore`), `home_layout_by_class` (`SizeClassLayoutStore`). The device copy is used only while its marker form equals the backed-up value, so an import or a platform restore wins over a stale copy. Values an older build stored with ids are moved to the device file on first read (migration). The state export (`layout` section and the `prefFiles` of the three arrangement files) is rewritten the same way, and import rewrites an older file that still holds ids, so a marked widget is a widget that lost its binding: HOM-07 (`WidgetStartup`) plans a rebind from the provider recorded in the item, or a placeholder if the provider is missing (`WidgetMarkerRebindTest`). The dock stream's `liftoff_workspaces.json`: the per-workspace widget lists now live in `noBackupFilesDir/liftoff_workspace_widgets.json`, keyed by workspace id; the main file keeps empty lists (read as "never saved", so a restore changes no widgets); an older file is migrated on first read; a removed workspace drops its list (`WorkspaceWidgetIdsBackupTest`). Tests: `WidgetIdSplitTest`, `WidgetMarkerRebindTest`, `WorkspaceWidgetIdsBackupTest`, source scans in `StateGapsAuditTest`, the existing `StateBackupExclusionTest` (all preference files classified). Stated limits: the rewrite is a text rewrite of the stored value, so a label that literally contains `widget:<digits>` is changed in the backed-up copy (the device copy keeps it); snapshots and exports are made from the same rewrite, so restoring one rebinds widgets through HOM-07 (consent may be asked) instead of keeping ids; the platform-restore guard still covers backups made before this change.
