# Home surface, workspaces and dock audit, wave 6 (stream "auditHomeWsp"): status

An independent re-read of HOM-01 to HOM-21, WSP-01 to WSP-12 and DCK-01 to DCK-08 against the code, the wiring and the tests. Status vocabulary as in earlier waves: built = compiles and is covered by JVM or Robolectric tests; partial = some of it is built or wired and a device or owner step remains. Nothing here is device-confirmed; no row was checked on a device.

How the audit was done. For every ID the row in `docs/SPEC_STATUS.md` was read against the spec text, the named tests were located by ID (`HOM_nn_`, `WSP_nn_`, `DCK_nn_`), and the main path was followed from the screen, registry or manifest to the code. Rows below say what was verified. Where a row says "read and wired, no defect found" the check was reading the path and the test names, not a re-derivation of every acceptance clause.

Defects found and fixed (each has a test that fails without the fix):

1. WSP-12 / WSP-07, state loss. `AutomationReceiver` and `RunActivity` switch workspaces with whatever hooks are installed. The hooks are installed by the composed `DockLayer` and were reset to a no-op when it left composition, so a switch asked for by a broadcast while the launcher screen was gone changed the active workspace without capturing the home being left; the next `applyActive` then overwrote the live home with the other workspace's saved arrangement, and the left workspace's unsaved layout was lost. Now `WorkspaceHooks.ready` is false for the stand-in hooks (`WorkspaceRepository.DETACHED`), the switch still happens at once, and `DockWorkspaceState.captureDue` records which workspace the live home still belongs to. It is stored in the workspace document (so a process death in between loses nothing); `applyActive` saves the live home into that workspace first, then applies the active one. Deleting that workspace clears the debt. Tests `WSP_12_aSwitchMadeWhileNoHomeIsComposed...` and `WSP_12_deletingTheWorkspaceThatOwnsTheLiveHome...`.
2. HOM-12, undo that could not undo. Removing a link, shortcut, widget or stack in edit mode dropped its definition and size from the extras, and the widget id was destroyed; undo restored only the page keys, so the restored key pointed at nothing (and the next reconcile prunes such a key). Folder creation and dissolve left the folder state out of step with the restored pages in the same way. New `EditGraveyard` (core-catalog), driven by `HomeEditHooks` from `HomeEditState` and implemented by `HomeItems`: while edit mode is on, removals keep their definitions and the app widget id stays bound; undo and redo restore the definitions and the folders for what moved at the top level (and leave unrelated edits such as a folder rename alone); leaving edit mode destroys the widget ids that stayed removed and drops the orphan definitions. Tests `HOM_12_*` in `EditGraveyardTest`. Remaining gap, stated in HOM-12 below: moves to the dock are not part of the layout undo.
3. HOM-10, crash. The package callbacks of `LauncherAppsAppRepository` ran `getActivityList` on the callback thread with no guard; a profile that cannot be read at that moment (locked, just removed) would throw there and take the process down. Now a failed read skips that snapshot (never emits a short one, which would make the missing profile's apps look uninstalled). Guarded by `HOM_10_aPackageCallbackCannotTakeTheProcessDown` (source audit; the callback needs a device to exercise).
4. WSP-01, a launch that bypassed the launch layer: the Launchpad's fallback for an app that is not in the inventory started the package launch intent directly. It now goes through `AppLauncher` with a `LaunchRequest`. Audit test `WSP_01_appsAreStartedOnlyThroughTheLaunchLayerExceptTheNamedFallbacks` fails if another `startMainActivity` appears outside `LaunchExecutor`, safe mode (`AppRepository`) and the no-hook fallback of `ActionRunner`. New `WSP_01_*` unit tests in `LaunchRequestW6Test` (the result names each dropped placement, once per session per reason, every reason has a text). Note: the media tile's "open player" fallback (`MediaNow.openPlayer`) still starts the package launch intent directly; it lives in `core-data`, which cannot reach `core-launch`, and the session's own activity is tried first. Left as is and listed here.
5. WSP-11 / WSP-05, untranslated and silent. The scheduled-launch notification ("Tap Open to start it", the "Open" action, its channel name), the group switcher notification and "Nothing to open" were English only; they now go through `L10n` (table `L10nW6auditHomeWsp.kt`, eight languages). With notifications switched off for the app both the scheduled launch and the group's quick switcher produced nothing and said nothing; the schedule toast and the group run now say that notifications are off (`QuickSwitcher.post` returns whether it could post; test `WSP_05_theQuickSwitcherSaysSoWhenNotificationsAreOff...`).
6. HOM-18, timeline day headings. The heading "In 3 days" / "3 days ago" was built in English before being passed to `L10n.tr`, so it never translated, and "Tomorrow" had no translation at all; and a day was 86 400 000 ms, so on a clock-change day (23 or 25 hours) an entry after midnight read "Today". `Timeline.dayParts` now gives a translatable key plus the number, and with a time zone it counts calendar days (`TimelineRow.dayKey/dayArg`, the panel passes the default zone). Tests `HOM_18_daysCountCalendarDaysAcrossAClockChange`, `HOM_18_dayHeadingsOfSeveralDays...`.
8. WSP-12, second review: `applyActive` applied the stale pre-save copy of the active workspace, so a switch away and back while no home was composed overwrote the live home. It re-reads the active workspace after the save now; test `WSP_12_switchingAwayAndBackWhileDetachedKeepsTheLiveHome`.
7. DCK-07, dead state. `DockHub.Instance.expanded` was only ever read by a test; the band's expanded state lived in a local of `DockHost`. It is now recorded on the display's own instance (the local remains the Compose state). `Instance.focusIndex` is still only used by the DCK-07 test (the rail keeps its focus in its own focus requester); left, not removed, because the test asserts it.

Dead code hunt. Candidates checked by searching every module for callers: `AppRepository.launch` (used only by the safe-mode screen, documented as such), `WallpaperScrollEffect` and `rememberHomeAccent` (called from `GridHome` and `HomeScreen`), `Timeline.build/dayLabel` (called through `TimelineView`), `SizeClassLayoutStore` (used by `HomeBehaviour`), `DockSearchProvider`, `WorkspacePaletteProvider`, `AppActionList.build/runDirect/pickerChoices` (all called from `HomeScreen`/`DockLayer`). Nothing else unreferenced was found in these streams apart from item 7.

New code: `core-catalog` `EditGraveyard.kt`; `app` `HomeEditHooks` in `HomeBehaviour.kt` and its implementation in `HomeItemsHost.kt`; `feature-dock` `Workspaces.kt` (`ready`, `captureDue`), `WorkspaceJson.kt` (optional `captureDue` field, schema version unchanged), `FileStore.kt` (`DETACHED`), `AppLauncher.kt`, `Automation.kt`, `DockHost.kt`; `core-catalog` `Timeline.kt`, `HomePanelModel.kt`; `core-data` `AppRepository.kt`; `core-design` `L10nW6auditHomeWsp.kt`. Tests added: `EditGraveyardTest` and `TimelineDayW6Test` (core-catalog), `WorkspaceTest` (two), `DockExtUiTest` (one), `LaunchRequestW6Test` (core-launch), `HomeWspW6AuditTest` (core-quality). No test was deleted or loosened.
